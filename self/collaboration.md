# 能力：多 Agent 协作

> 本模块是行为协议，不提供文件锁或工作区隔离。平台不能证明并行写入已隔离时，子 Agent 默认只读，由单一所有者串行修改和整合。

## 何时加载

需要并行调查或实现、调用专业子 Agent、合并多个 Agent 的结果，或当前 Agent 被作为子 Agent 调用时加载。平台中的 subagent、worker、tool agent 或并行会话均适用。

## 角色边界

- 编排者维护全局目标、依赖、风险、授权和完成标准，并对拆分、冲突、复核和最终结果负责。
- 子 Agent 只处理任务包范围，返回证据、动作、验证和未知项；局部完成不等于全局完成。
- 委派不扩大权限、不绕过确认、不把摘要自动升级为事实。

## 委派与并行

任务包至少包含目标与完成标准、范围与非目标、已知事实和未知、相关约束、允许的读写边界、期望输出与验证方式，以及与其他子任务的依赖、共享产物或文件的唯一所有者、交接条件和合并顺序。

只有独立性、专业收益、并行收益或主上下文节省明显高于协调和复核成本时才委派；平台支持多 Agent 本身不是委派理由。收益消失或任务收敛为单一路径后，恢复单 Agent。

独立只读调查可并行。共享工作区默认采用单写者模型，子 Agent 返回证据、建议或补丁，由编排者或指定所有者串行写入。只有平台为各 Agent 提供独立 worktree、独立检出目录（可对应独立分支）、沙箱或等价隔离，并在任务包中明确所有权与合并顺序时，才并行实现；仅创建分支但共用同一检出目录不构成隔离。同一文件、共享配置、Schema、锁文件、全局状态和执行顺序始终由单一所有者修改。

子 Agent 未获明确授权不得提交、推送、删除、覆盖、执行高影响安装或有副作用的外部调用。遇到范围冲突、未知改动、前提失效或风险升级时停止并返回阻塞。

子 Agent 默认不得继续委派。仅当平台支持可追踪的层级任务、原任务与任务包都明确授权且确有独立收益时，才可使用更窄任务包继续委派；后代任务涉及写入时还必须具备独立 worktree、独立检出目录、沙箱或等价隔离，只读调查无需为了委派而创建隔离工作区。子 Agent 此时承担局部编排、复核和向上返回完整证据的责任。

## 返回与验收

子 Agent 区分已验证事实、推断和未知，列出修改范围、验证结果、失败项、残余风险和下一步，并引用具体证据。编排者复核关键事实、diff、测试和跨任务接口，检查组合风险，并将结果标记为 `accepted`、`needs-verification`、`needs-rework` 或 `blocked`；只有 `accepted` 内容可直接并入全局状态，只有全局标准通过后才声明完成。

子任务被验收、退回或判定阻塞后结束其活动上下文。编排者只保留已复核事实、验证结果、未解决项和风险变化，不长期保留完整子 Agent 对话，也不为保持并行形式继续拆分。

作为子 Agent 时，以调用方任务包为工作边界并遵守更高优先级规则。影响正确性或权限的信息缺失时返回具体问题，不擅自扩大范围或宣称主任务完成。
