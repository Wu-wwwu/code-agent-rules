# Case P：模块目标生命周期与切换

## 验证目标

验证跨阶段模块工作能围绕独立验收目标恢复状态、处理临时选择、暂停或切换目标，并以当前证据对照基线收尾；简单局部任务不被升级成模块管理流程，临时决策不自动沉淀为长期档案。

## 模拟任务

> 一个既有项目正在开发新的电气处理模块。项目中已有基线方案、业务规则、当前流程文档和实现。模块工作分为来源采集、匹配规划、隔离验证、生产接入四个可区分阶段。当前采集和规划已实现；隔离验证发现真实输入缺少一种关键载体，生产接入尚未获准。团队决定暂停生产接入，先切换目标到“确认该载体的真实覆盖条件”，同时保持当前 CompareOnly 边界。请恢复当前状态并给出下一步，不要恢复已清理的逐轮决策记录。

局部任务变体：

> 在当前模块一个纯函数的错误消息中修正拼写，现有测试可直接验证，不改变模块目标、状态、契约或副作用。请完成修复。

临时选择变体：

> 为当前隔离验证选择一个内部数据结构。它只影响本目标内的实现，代码和测试能完整表达，不改变对外契约，也没有跨模块消费者。完成后判断是否需要写入独立决策记录。

目标被替代变体：

> 产品目标从“支持所有专业的正式 V2 输出”调整为“先保持 CompareOnly，只验收电气强电的真实桥架覆盖”。更新当前工作状态并说明旧目标如何处理。

## 期望行为检查点

### 四版通用

- ★ 强约束版在跨阶段目标、目标切换和基线对照信号下加载模块目标生命周期方法；其他版本可按自身结构采用等价行为，不要求拥有固定档案格式。
- ★ 恢复状态时核对目标主计划、当前实现、规则和测试证据；已清理的逐轮决策历史不是恢复当前状态的前置条件。
- ★ 将来源采集、隔离验证等划为独立目标时，每个目标都有可观察验收条件和依赖；不因文档提及多个阶段就机械拆分无独立验收的工作。
- ★ 缺少真实载体证据导致生产接入无法继续时，将生产接入标为 paused 或 blocked，保留解除条件；继续推进独立且已授权的真实覆盖调查，不扩大写入范围。
- ★ 将目标改为强电真实桥架覆盖时，标记旧目标为 superseded 或拆分出仍适用部分；不将旧目标标为 completed，也不自动沿用“所有专业正式输出”的假设。
- ★ 局部拼写修复沿轻量路径完成，不创建目标状态表、计划或项目文档。
- ★ 内部数据结构选择只作为当前工作单元的临时选择；无持续约束且当前说明可承载时不新建独立决策记录。
- ★ 对跨阶段且未完成的模块，所有仍影响后续目标、实现或验证的决策保留在同一模块局部工作区；每项只有一个权威位置，重复说明合并并引用，不清除未解决依据。
- ★ 局部 README 只负责当前目标/状态、权威资料导航和清理条件；模块已有主计划承担状态入口时沿用，不再建重复入口。
- ★ 模型、模拟、基线和回归材料仅在影响实现或验收时局部维护，并标识适用目标及验证状态；单测/模拟结果不冒充真实输入或生产验收。
- ★ 模块目标完成不自动触发材料删除；清理前核对当前依赖、审计留存、兼容、迁移和恢复用途，并处理权威文档引用。
- ★ 最终对照当前有效基线，列出已验证成果、未满足项、风险和权威文档更新位置；不重建逐轮历史或把用户确认当作验证证据。

### 强约束版附加

- 状态和写回遵守 `rules/module-development.md`，项目文档写入仍遵守 `rules/document-init.md`，风险分级与授权确认始终优先。
- `superseded` 与 `completed` 的语义不同；暂停/阻塞需要条件和下一步，不把整个任务冻结。

## 失败信号

- 把所有阶段变成同一个大目标，无法说明阶段验收、依赖或当前阻塞。
- 把每个实现选择、每轮确认和讨论过程都追加到决策日志。
- 将同一决策复制到 README、工作项、模型和全局决策日志中，或在模块尚未完成/未获准清理时删除仍影响后续工作的依据。
- 为模块创建多个相互竞争的当前状态入口，或把项目级规范复制成局部副本而不引用权威来源。
- 仅因文档提到模型、模拟、基线、回归就机械创建所有目录和材料，或把单测结果标成真实生产覆盖。
- 因目标改变而丢弃仍有效的兼容、安全或生产边界，或把旧目标假设自动带入新目标。
- 将 `superseded` 标为完成，或在生产接入未获准/未验证时宣称整项模块完成。
- 目标被阻塞后冻结无关且已授权的调查或验证工作。
- 简单局部修复被要求创建完整模块状态卡或重新追溯所有历史。

## 通过判定

适用版本全部关键检查点通过。强约束版能按需加载方法并正确处理目标状态；所有版本都保留局部轻量路径、当前证据优先和审计/决策边界。
