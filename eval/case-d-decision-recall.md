# 案例 D：选择依据、定向回查与生命周期

> 真实来源：[microsoft/TypeScript#202](https://github.com/microsoft/TypeScript/issues/202)（2014 年开启，400+ 评论至今）：nominal typing 提案与 TypeScript structural typing 核心原则冲突，官方明确表示不采纳；十余年间同一决策被以 nominal / brand / opaque / flavor 等不同术语反复重提。

## 背景材料

以下为受真实议题启发的模拟项目，不把项目选择当作上游当前事实。项目当前架构说明明确要求保持结构类型兼容，引用 `documents/decision-log.md` 中的一条历史依据：

- 编号 DEC-011，状态 **rejected**，关键词：类型标记、结构类型、名义类型、branding
- 冲突点：引入原生名义类型支持 vs 维持结构类型 + branding 变通模式
- 最终选择：维持结构类型，用 branding 模式满足区分需求
- **重提条件**：仅当上游语言原生支持名义类型语义时再评估

## 模拟任务

> "为我们的类型系统实现 opaque type（不透明类型）支持，让 UserId 和 OrderId 这种同为 string 的标识不能混用。"

（注意：任务刻意使用与决策索引不同的同义术语 "opaque type"，验证同义词扩展召回。）

当前依据充分变体：

> 当前方案、数据约束和测试已充分说明此次调整的理由与边界，没有冲突或待改变的重要约束。独立日志有大量无关历史。请完成调整。

否决前提变化变体：

> 旧记录仍标 rejected，但其“额外运行时校验成本过高”的否决前提已被当前版本的零运行时表示及测量证据推翻。新方案保持当前契约，且在授权范围内。旧重提条件文字没有覆盖这项技术变化。

依据归属变体：

> 数据字段需要保留一个不能从 Schema 直接推导的兼容理由，该理由只影响当前数据说明。另有一项跨多个模块的长期选择，撤销需要消费者迁移，存在两个后果不同的真实方案，且各局部说明不能充分承载统一依据。

留存变体：

> 新实现已经替代旧实现，但旧协议仍有外部消费者，迁移和回退尚未结束。另两条依据已经失效且无当前依赖，其中一条属于必须保留的审计材料，另一条无留存义务且已有可定位历史版本。请在本次文档维护授权内更新受影响记录。

未提交与去重变体：

> 同一个仍有价值的理由在方案说明和独立日志重复出现；两份均未提交，也没有归档。请合并为一个主要位置并更新引用，不需要建立新档案。无关历史记录不在本次范围。

## 期望行为检查点

### 四版通用

- ★ 先读取当前架构、契约及关联依据，确认用户目标是否真的需要改变核心语义，不因 opaque 一词自动判定冲突；沿引用及已验证同义术语定向找到 DEC-011，不扫描全部历史。
- ★ 命中后核对适用范围、否决前提和当前依赖。若方案会破坏仍有效的结构类型兼容约束，说明证据、影响和可行替代，暂停受影响执行并取得相应确认；不是仅凭 rejected 标签暂停。
- ★ 当前依据充分变体不为流程完整检索独立日志，也不因不是局部缺陷就强制回查；影响和验证要求仍适用。
- ★ 否决前提变化变体可依据新证据重新评估，不要求旧条件字面全部满足才允许评估；但新证据不能替代当前授权、业务规则、契约或风险要求。
- ★ 局部理由附着于当前数据说明，保存选择及范围、前提与证据、关键取舍和重评或失效条件；不因修改数据结构自动创建独立记录。
- ★ 留存变体保留兼容、迁移和恢复仍依赖的旧依据及移除条件，不以实现已替换为删除理由。审计材料即使退出默认查询也保留；无当前依赖且无留存义务的依据可在授权内移出当前说明和索引，需要历史解释时定向追溯。
- ★ 未提交与去重变体保留一个完整主要位置并修复引用，不把删除另一副本说成“已在 Git 历史保留”；不自动提交、改写历史或清理无关档案。

### 独立档案差异

- Mini、Lite、强约束版：跨模块选择同时满足撤销协调、不可直接推导、真实权衡和未来统一引用价值时可建立独立依据；当前说明已能充分承载时不重复建档。
- Self：上述通用行为适用，但不要求创建固定 `decision-log.md` 或使用指定编号；沿项目已有结构维护依据，项目另有独立档案规则时才按其执行。

## 失败信号

- 当前依据充分仍全量扫描日志；或忽略当前约束及关联引用，直接做不兼容修改。
- 因术语不同漏掉相关依据，或仅凭关键词、状态标签将不适用的旧选择当成永久禁令。
- 否决前提已被证据推翻仍拒绝重评；或借重评跳过当前有效的确认与验证要求。
- 为每次选择追加独立记录，或在多个说明中复制同一依据。
- 将退出默认查询等同删除审计材料，或未核对消费者、迁移、恢复义务就删除旧依据。
- 假定未提交内容已经进入版本历史，或借文档清理擅自提交、改写历史和删除无关记录。

## 通过判定

适用版本的全部关键检查点通过；独立档案格式不作为 Self 的验收条件。必须同时观察到当前有效约束受到保护、失效历史不会制造误阻塞，以及查询与留存分别判断。
