# 多 Agent 协作

> **进入**：独立子任务并行调查或专业复核的收益高于拆分、传递、整合和复核成本；小型串行任务跳过。

## 最小任务包

每个子任务只接收完成自身目标所需的最小上下文，但至少明确：

- 子任务目标、可观察完成标准、范围与非目标；
- 允许读取、允许写入和禁止操作的边界；
- 已验证事实及证据位置、待验证推断、未知和冲突；
- 与当前子任务相关的架构、契约、兼容要求、风险和权限门禁；
- 与其他子任务的依赖、共享资源所有者和合并顺序；
- 期望返回格式、验证命令或验收证据。

不得把完整主任务叙事无差别复制给子 Agent；也不得用摘要隐藏证据缺失。子 Agent 可以验证任务包中的事实，影响正确性或权限的信息不足时返回具体阻塞问题。

## 并行与写入

- 只读调查可并行；共享工作区默认单写者。
- 只有独立工作区、所有权和合并顺序明确时才并行写入。
- 同一文件、共享配置、Schema、锁文件或全局状态只由一个所有者修改。
- 子 Agent 默认不得继续委派，也不得扩大原任务权限。

## 返回与验收

子 Agent 至少返回：已验证事实、推断与未知、证据位置、采取的动作、修改范围、验证结果、残余风险和建议下一步；不得把局部完成宣称为全局完成。

主 Agent 必须复核关键事实、diff、测试和跨子任务接口，处理冲突假设、重复修改与遗漏，并将结果标记为 `accepted`、`needs-verification`、`needs-rework` 或 `blocked`。只有已验收结果才能并入全局状态；子任务成功不等于全局完成。

结果已整合并通过全局成功标准后退出；任务收敛为单一路径时恢复单 Agent 执行。
