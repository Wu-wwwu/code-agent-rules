# 多 Agent 协作方法

> **触发条件**：任务可拆分为独立子任务、需要并行调查多个模块、需要不同专业域审查。
> **适用判定**：只有委派收益高于任务拆分、上下文传递、整合和复核成本时才扩展；小型串行任务保持单 Agent。

## 任务包契约

委派前至少传递：

```markdown
## 任务包

### 目标
<一句话描述>

### 范围
- 允许读取：<路径列表>
- 允许写入：<路径列表（通常为空）>

### 完成标准
<可验证的条件>

### 已知事实
<已验证的事实及证据位置>

### 返回格式
- 已验证事实：<列表>
- 采取的动作：<列表>
- 验证结果：<通过/失败/无法验证>
- 残余风险：<列表>
- 建议下一步：<描述>
```

## 并行与写入规则

- 只读调查可并行
- 共享工作区默认采用单写者模型
- 只有能证明独立工作区并明确所有权、合并顺序时才并行写入
- 子 Agent 默认不得继续委派

## 结果验收

主 Agent 接收后必须：
1. 检查结果是否满足任务包
2. 对关键事实、代码 diff、测试进行复核
3. 检查重复修改、冲突假设、遗漏影响
4. 只有全局成功标准通过后才声明完成
