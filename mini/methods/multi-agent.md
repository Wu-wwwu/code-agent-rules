# 多 Agent 协作

> **进入**：子任务有独立完成标准、不依赖尚未产生的前序结果，且适合只读并行、隔离且有唯一所有者的写入，或需要独立专业证据。主 Agent 一次工具调用/一个局部动作可完成、必须串行等待、同一文件或共享状态无法划分所有权、需要主 Agent 作授权/业务/不可逆选择时跳过。

## 最小任务包

每个子任务只接收完成自身目标所需的最小上下文，但至少明确：

- 子任务目标、可观察完成标准、范围与非目标；
- 允许读取、允许写入和禁止操作的边界；
- 已验证事实及证据位置、待验证推断、未知和冲突；
- 与当前子任务相关的架构、契约、兼容要求、风险和权限门禁；
- 与其他子任务的依赖、共享资源所有者和合并顺序；
- 期望返回格式、验证命令或验收证据。

不得把完整主任务叙事无差别复制给子 Agent；也不得用摘要隐藏证据缺失。子 Agent 可以验证任务包中的事实，影响正确性或权限的信息不足时返回具体阻塞问题。

## 并行与写入

- 只读调查可并行；共享工作区默认单写者。
- 只有独立工作区、所有权和合并顺序明确时才并行写入。
- 同一文件、共享配置、Schema、锁文件或全局状态只由一个所有者修改。
- 子 Agent 默认不得继续委派，也不得扩大原任务权限。

## 返回与验收

子 Agent 至少返回：已验证事实、推断与未知、证据位置、采取的动作、修改范围、验证结果、残余风险和建议下一步；不得把局部完成宣称为全局完成。

主 Agent 必须复核会影响全局结论、写入安全、共享契约或跨子任务接口的事实，并检查完整 diff 与相关测试；其他事实可按风险抽样但标注未复核范围。处理冲突假设、重复修改与遗漏，并将结果标记为 `accepted`、`needs-verification`、`needs-rework` 或 `blocked`。只有已验收结果才能并入全局状态；子任务成功不等于全局完成。

结果已整合并通过全局成功标准后退出；任务变成串行链、写入边界重叠，或协调与复核步骤不再少于主 Agent 直接完成所需步骤时，恢复单 Agent 执行。
