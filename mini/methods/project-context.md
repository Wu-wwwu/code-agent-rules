# 项目上下文

> **进入**：新增功能、计划、跨模块修改、上下文恢复，或实现路径/验证接缝不足以安全行动。
> **跳过**：行为未越过公开契约、Schema、共享配置/状态、安全权限、生产副作用或新增消费者边界，且已有可复用的同范围上下文。

## 最小路径

1. 明确目标、成功标准、范围与非目标；关键歧义先核对有效要求与现有证据，仍影响动作且无法消除时再请求必要澄清。
2. 证据取得后来源、目标、范围、分支/环境和相关依赖未变化，结果未截断/部分失败且无更新冲突时复用；否则只补会影响动作或完成判断的部分。
3. 从用户可观察入口沿调用、数据、配置和依赖追到输出与验证接缝；验证接缝是可独立断言响应、持久化状态、消息/文件产物、指标或测试接口的位置。追到本任务不修改、契约明确且能说明后续影响与成功标准无关的稳定边界即停止。
4. 只保留会否决方案、限制写入、改变风险或影响验收的约束；命中专项信号再加载对应方法。
5. 形成可追溯到目标、路径节点或验证缺口的最小计划；实际结果不符时刷新上下文。

最小上下文仅含：目标与验收、范围/非目标、相关实现事实及证据、入口到输出的情景路径、关键约束、待验证推断、未知/冲突、下一动作及验证。不能说明某信息如何影响当前动作时，不继续收集。

这里构建的是当前任务所需的环境切片，不是完整项目模型：项目事实提供候选背景，情景路径描述当前入口、变换、状态、输出与观察点，任务环境只保留其中会影响当前动作、风险或验收的部分。

## 需求转检索与探索纠偏

- **需求转检索目标**：从当前任务提取可观察行为、约束与验收，区分明确要求、待验证描述和推定验收，定位入口、数据、规则和验证接缝。描述中的术语仅作检索线索，对应关系以符号、引用、Schema、配置或测试为证。
- **锚点与纠偏**：关键探索方向明确依据和预期命中，不要求逐次播报；未命中先核对检索范围和必要的命名变体，假设被证伪或仍无支持证据再切换另一类锚点（入口/路由、数据/Schema、测试、日志、配置、已验证术语映射），不沿同一假设无依据地反复扩搜。
- **复用与新增**：新建前检查可复用或可扩展的现有实现；在已检查范围内未发现适用实现时，说明范围、证据、未覆盖区域及新增理由，再在授权内新增，不声称全局“不存在”或穷尽无关路径。
- **文档按条盘点**：仅核对任务相关条目，标记为一致、过期/冲突、缺失或无法验证，不整份重建。描述性条目按已验证事实更新；规范性冲突先据有效契约或用户确认判定修代码还是修文档，不以实现或测试覆盖规范。
- **未知分流**：可自主验证的先取证；目标/范围/验收/业务语义/契约有待裁决的歧义，或缺少无法自行获取的关键信息、权限或操作授权时，再请求必要澄清、资料或授权，注明受影响动作和已有证据。不影响当前动作的未知标注后继续，只暂停受阻动作。
- **导航经验写回**：任务文档维护不限于导航信息；导航事实（术语→代码锚点、命令、项目约定）仅在授权内按需写回，须已验证且可复用，附来源与失效条件，不记录探索过程，不自动创建文档。

## 结论与委派

上下文中的结论应区分：已验证事实及证据、待验证推断、未知、来源冲突和约束。文件存在、名称相似、历史摘要或示例文档都不能自动升级为当前事实。

需要委派时，将全局上下文投影为子任务包，只传递与子任务目标、边界、依赖、风险和验收有关的信息，并保留关键证据位置供接收方复核；不要复制完整项目叙事，也不要省略会改变正确性或权限判断的上下文。

仅在实际读写目标项目的 `documents/*.md` 时，再加载 `methods/project-documents.md`；项目文档不是默认前置条件。复杂 Bug、技术选择或历史回查分别再加载对应方法，不重复扫描。

## 最小充分模型

新增入口、数据表示变化、事务或外部副作用需要推导，或改动将改变既有执行顺序、状态转换或副作用时机时同样适用本方法；局部且直接可验证的修改不要求额外建模。

建模结论描述系统当前的职责、约束与行为，实现路径描述如何修改；两者分开维护，不用实现便利性倒推领域模型。模型与实现证据冲突时以实现为准并标记，目标行为仍以有效需求和业务规则为准。

- 从用户可观察路径确认改动点、关键不变量、验证接缝，以及必要的数据转换和失败处理；三要素足以支持当前动作即转入实现，不为完整地图扩展模型。新证据使前提失效时只重开受影响部分。
- 改动会改变执行顺序、状态转换或副作用时机时，关键不变量必须显式覆盖：受影响调用链（入口→关键节点→出口）、状态转换（状态集合、允许与非法转换）、步骤间顺序依赖，以及副作用（DB/缓存/消息/外部调用/通知）相对事务边界的位置；未受影响的维度不要求枚举。
- 按实际代码职责选择可组合的表示：数据访问关注数据/存储结构，业务处理关注模型/不变量，算法关注数据结构/复杂度，边界编排关注契约/映射/副作用；不依据文件名或预设分层强行套用。
- 内存变换关注进程内表示、可变性、生命周期、不变量和计算；持久化处理关注存储模型、事务、提交可见性、并发、幂等、恢复和迁移。序列化、缓存、队列等边界单独验证，不自动拆成目录或类层次。
- 编码方向按问题目标、职责边界、数据表示、变换过程、状态生命周期、控制流、副作用和验证接缝推导；设计模式、编程范式和分层结构只是可选表达方式，不能在证据不足时作为实现起点。
- 涉及数据保留或变换时，按实际路径区分内存生命周期、持久化时机、缓存生命周期、消息发送/确认时机以及外部调用/通知时机；只在某一边界影响当前动作、正确性、恢复或验收时建模该边界。
- 创建模型只为解释当前职责、约束、变换、生命周期或验证边界；模型不能改变当前动作或完成判断时，不继续扩展模型，也不自动将模型写入项目文档。
- 状态按实际需要区分业务、数据有效性、执行控制、持久化一致性、并发版本和外部副作用，不把不同维度混为一个状态字段。

## 退出

目标与范围足以行动、相关实现路径和约束已定位、下一动作可验证，且剩余未知不影响该动作或已转为明确阻塞时立即退出。不要为“完整了解项目”扩展上下文。
