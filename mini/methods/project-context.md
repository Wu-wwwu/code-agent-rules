# 项目上下文

> **进入**：新增功能、计划、跨模块修改、上下文恢复，或实现路径/验证接缝不足以安全行动。
> **跳过**：局部、直接可验证且已有新鲜同范围上下文。

## 最小路径

1. 明确目标、成功标准、范围与非目标；关键歧义先询问。
2. 复用当前会话证据，只补缺失、过期、冲突或范围变化部分。
3. 从用户可观察入口沿调用、数据、配置和依赖追到输出与测试/观察点；到稳定边界即停止。
4. 只保留会否决方案、限制写入、改变风险或影响验收的约束；命中专项信号再加载对应方法。
5. 形成可追溯到目标、路径节点或验证缺口的最小计划；实际结果不符时刷新上下文。

最小上下文仅含：目标与验收、范围/非目标、相关实现事实、入口到输出路径、关键约束、未知/冲突、下一动作及验证。不能说明某信息如何影响当前动作时，不继续收集。

若需读取或写入目标项目长期记忆，再加载 `methods/project-documents.md`；项目文档不是默认前置条件。复杂 Bug、技术选择或历史回查分别再加载对应方法，不重复扫描。

## 退出

目标与范围足以行动、相关实现路径和约束已定位、下一动作可验证，且剩余未知不影响该动作或已转为明确阻塞时立即退出。不要为“完整了解项目”扩展上下文。
