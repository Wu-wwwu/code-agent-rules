# 项目上下文与实现路径方法

> **触发条件**：新增功能、制定或修订实现计划、跨模块修改、上下文恢复、用户改变目标，或影响边界/实现路径不清。
> **目标**：形成能改变当前方案、动作或验证结论的最小项目认知，不构建与任务无关的完整项目地图。
> **轻量路径**：简单、局部、直接可验证且已有新鲜完整上下文的任务，不构造上下文包，只读取下一动作必需的证据。

## 上下文来源与优先级

按当前问题选择来源，不要求全部读取：

1. 用户本轮确认的目标、约束、成功标准和非目标；
2. 代码、配置、Schema、测试、日志和运行结果；
3. 构建清单、入口、依赖引用、版本历史和部署配置；
4. 目标项目中有效的 `documents/project-doc.md`、`architecture.md`、`tech-stack.md`、`data-flow.md`、`business-rules.md`、`decision-log.md`、`coding-standards.md` 和 `glossary.md`；
5. 基于上述证据的待验证推断。

读取或初始化项目文档前遵循 `methods/project-documents.md`。示例、占位、无来源摘要和与当前实现冲突的内容不得作为项目事实。

## 最小任务上下文包

只保留本次任务需要的字段；简单任务可在内部维护，不必完整输出：

| 字段 | 内容 | 最低证据要求 |
|------|------|--------------|
| 用户目标与成功标准 | 最终结果、可观察完成条件 | 用户输入或已确认验收 |
| 非目标与范围 | 本次不做什么、允许读写边界、兼容要求 | 用户输入、仓库边界或现有契约 |
| 项目目标关联 | 当前任务服务或可能冲突的项目目标/能力 | 有效项目说明、README、用户确认或可验证产品行为 |
| 当前实现事实 | 与任务直接相关的入口、模块、配置和行为 | 代码、配置、测试或运行结果 |
| 功能实现路径 | 入口→核心模块→数据/外部依赖→输出→测试/观察点 | 调用、引用、映射、配置和测试证据 |
| 当前约束 | 架构、业务、安全、兼容、技术和作用域约束 | 对应事实或有效决策来源 |
| 未知与冲突 | 尚未验证、证据不一致或需要用户裁决的内容 | 明确标记，不伪装为事实 |
| 下一动作与验证 | 最小动作、成功/失败信号和验证方式 | 能直接推进目标或降低关键不确定性 |

不能说明某一字段如何影响当前动作时，不为填表而继续调查。

## 构造步骤

1. **校准任务**：确认目标、成功标准、范围和非目标；关键歧义会改变实现时先询问。
2. **复用上下文**：检查当前会话是否已有新鲜、直接、同范围证据；只有缺失、过期、冲突或范围变化时补读。
3. **定位项目关联**：确定任务属于哪个功能/能力，或明确它与项目目标无直接关系；不得仅凭文件名推导产品语义。
4. **追踪实现路径**：从用户可观察入口沿调用、数据、配置和依赖追踪到输出与验证接缝；到达稳定边界即停止，不扫描无关区域。
5. **提取约束**：只保留会否决方案、限制写入、改变风险或影响验收的约束；必要时加载对应专项方法。
6. **形成计划**：让每个步骤能追溯到目标、路径节点或验证缺口；不把“阅读所有文档”当作默认步骤。
7. **决策点共址**：在真正受约束的计划、工具调用或修改点旁，用完整自然语言重述当前最关键约束。
8. **验证并刷新**：实际结果与上下文不一致时更新事实、未知和下一步，不为维护旧计划而忽略新证据。

## 不同任务的最小扩展

- **新增功能/实现计划**：项目目标关联、功能边界、入口到输出路径、架构/技术约束、测试接缝。
- **Bug**：预期行为、实际行为、复现入口、受影响路径、最近变化和可观察点；复杂 Bug 另加载 `methods/bug-diagnosis.md`。
- **跨模块修改**：模块职责、依赖方向、共享契约、数据/状态传播和稳定边界。
- **技术选择**：现状、硬约束、候选方案影响和验证方式；存在真实方案空间时另加载 `methods/technology-selection.md`。
- **历史约束**：只有当前选择可能重复或冲突历史决策时，加载 `methods/decision-recall.md`。

## 写回长期项目记忆

只有同时满足以下条件时，才建议按 `methods/project-documents.md` 写回目标项目的 `documents/`：

1. 内容已由代码、配置、测试、运行结果或用户确认验证；
2. 后续任务具有跨会话复用价值；
3. 不是一次性执行步骤、临时假设或未清理的调试信息；
4. 写入位于本次授权范围，且不会覆盖项目已有自定义结构。

写回后回读并核对来源。推断必须标记“待确认”；实现变化使旧记录过期时，更新或标记冲突，不静默保留两个互相矛盾的事实。

## 停止条件

满足以下条件即可退出本方法，恢复 anchors 普通路径：

- 当前目标、范围和成功标准已足以行动；
- 已确定与本轮有关的实现路径和约束；
- 下一动作有明确预期与验证方式；
- 剩余未知不会影响当前动作正确性，或已转为明确阻塞/待确认项。

不要为“环境完整”持续扩展上下文；上下文的价值以是否改善当前决策和验证为准。
