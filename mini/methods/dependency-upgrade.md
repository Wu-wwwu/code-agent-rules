# 依赖升级

> **进入**：major 升级、弃用到期或上游移除。无破坏信号的普通 patch/minor 更新走轻量路径。

1. 修改版本或代码前，检查上游 breaking changes，以及声明/锁文件、配置、生成物、CI/CD、容器、部署环境和下游消费者，形成影响清单。
2. 记录 API、配置、行为和数据影响；宽迁移采用“扩展 → 分批验证 → 收缩”，不要一次切换。
3. 存在不兼容契约、数据/认证语义或高风险迁移时，先加载 `methods/destructive-analysis.md` 完成分级、方案与授权门禁，再执行修改。
4. 数据删除语义、默认值、序列化格式、权限或认证存在真实选择时，不得默认决定；逐处或分类请求确认。
5. 执行后验证构建、测试、生成物、迁移、CI/CD 和部署产物，并比较预测与实际影响。
6. 保留可复现的版本/步骤和可行回退；不可逆数据迁移必须有迁移与恢复方案。

所有实际采用升级的环境和产物均通过验证，且破坏性义务完成后退出。
