# 可选项目文档方法

> **触发条件**：专项方法准备读取或写入目标项目的 `documents/*.md`。
> **定位**：`documents/` 是可选的长期项目记忆，不是规则运行或每个任务的默认前置条件。

## 读取前检查

1. 先确定目标项目根目录；不得把规则仓库自带的示例目录、文件系统根目录 `/documents/` 或其他项目的文档当成当前项目事实。
2. 只检查当前动作需要的文件，不因进入项目就创建或全文读取整个目录。
3. 将目标文件分类为：
   - **有效**：内容有来源，且适用于当前项目和当前范围；
   - **缺失**：目录或文件不存在；
   - **示例/占位**：含 `EXAMPLE`、`示例`、`待替换` 等标记，或没有真实来源；
   - **过期/冲突**：与当前代码、配置、Schema、测试、运行结果或用户说明不一致。
4. 只有“有效”内容可以作为项目事实；示例、占位和冲突内容只能作为格式参考或待核实线索。

## 文档职责

| 文件 | 用途 | 主要来源 |
|------|------|----------|
| `documents/project-doc.md` | 项目目标、用户/场景、范围、主要功能与成功标准 | 用户确认、README、可验证产品行为 |
| `documents/architecture.md` | 系统边界、模块职责、依赖方向、入口与运行/部署拓扑 | 代码、配置、部署文件、运行证据 |
| `documents/tech-stack.md` | 当前实际使用的语言、框架、存储、工具链及版本来源 | 声明文件、锁文件、配置、构建结果 |
| `documents/data-flow.md` | 关键功能从输入到输出的数据、状态和外部依赖路径 | 调用、Schema、查询、消息、测试、追踪 |
| `documents/business-rules.md` | 有证据锚点的业务规则 | 代码、Schema、测试、用户确认 |
| `documents/decision-log.md` | 需跨会话回查的技术决策及状态 | 决策记录、提交历史、用户确认 |
| `documents/coding-standards.md` | 项目特有且能由工具/代码验证的编码与测试约定 | lint/format/test 配置、代码惯例、CI |
| `documents/glossary.md` | 术语、代码实体、存储名之间的已验证映射 | 代码、配置、Schema、用户确认 |

缺失只表示对应持久化记录当前不可用，不表示项目没有目标、架构、技术约束、数据路径、规则、决策或术语。需要当前任务上下文时加载 `methods/project-context.md`；只有内容已验证且具有跨会话复用价值时才写回文档。

## 缺失时的降级

- 项目目标、架构、技术栈、数据流或编码标准文档缺失：从用户说明、README、代码、配置、声明/锁文件、测试、运行和部署证据构造当前任务所需的最小事实；不得为补齐目录而阻塞任务。
- `business-rules.md` 缺失：从用户确认、业务资料、代码判断、Schema 和测试中定位目标行为；没有可验证依据时暂停语义裁决，不得推测。
- `decision-log.md` 缺失：明确说明“没有可用的决策档案，无法证明不存在历史决策”，再从提交历史、讨论记录、代码注释和当前证据补充检索；若仍无记录，按当前任务证据继续或在高影响冲突处请求确认。
- `glossary.md` 缺失：按 `methods/data-entity-analysis.md` 使用用户用词、代码标识、Schema、表和搜索结果扩展定位；不得因词表缺失而停止普通检索，也不得从名称自动引入现实领域语义。

## 按需初始化

只有同时满足以下条件时才创建或更新文档：

1. 当前任务需要形成可复用、跨会话的项目记忆；
2. 已获得至少一条可定位的真实证据，或即将记录一个满足建档条件的决策；
3. `documents/` 位于本次任务允许修改的项目范围内；纯查询、只读审查或范围不明时不写入，可返回待落盘草案并请求确认。

初始化步骤：

1. 创建 `documents/`（仅当目录不存在）。
2. 只创建当前需要的单个文件，不批量生成整套文档。
3. 写入最小标题、证据边界和必要表头；不复制演示业务数据。
4. 立即写入本次已验证条目及来源；没有真实内容时不创建空壳。
5. 回读文件，确认没有把推断写成事实；推断必须标记“待确认”。

```markdown
## 范围与非目标

## 当前限制与未知
```

```markdown

## 索引

|------|------|------|--------|

## 决策记录
```

```markdown

|----------|------|-----------|----------|
```

```markdown
# 术语表

> 仅记录已由代码、Schema、配置、查询、测试或用户确认的映射。名称中的现实概念默认只是数据标签，不代表已确认的行业语义。

| 数据实体标识 | 中性名称 | 用户术语 | 代码/Schema 表示 | 存储表示 | 关系/变换 | 证据来源 |
|--------------|----------|----------|-----------------|----------|-----------|----------|
```

## 更新边界

- 当前实现以代码、配置、Schema 和运行结果为准；目标行为以有效业务依据和用户确认为准。
- 项目目标、架构、技术栈、数据流和编码约定中的稳定事实也必须附来源；相关实现变化后复核对应记录。
- 术语映射用于定位数据构件和保持表示关系；除非现实语义有明确证据且当前任务需要，不把同名数据实体解释为现实物品或自然概念。
- 文档与实现冲突时先标记冲突，不静默覆盖任一方。
- 项目已有自定义结构时沿用其结构，只补当前任务需要的最小字段。
- 规则条目可使用 `R-<领域>-<序号>`，决策条目可使用 `D-<YYYYMMDD>-<序号>`；不编造日期、状态、owner、来源或 ID。
- 写入后立即回读并核对内容；初始化模板不代表已经补齐事实。
