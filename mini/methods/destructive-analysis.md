# 破坏性分析

> **进入**：删除/覆盖数据、改权限或安全、覆盖配置、产生外部副作用，或改变公开 API、Schema、共享契约。

## 分析与分级

1. 列出变更元素：目标环境、操作、对象/数据范围、契约与消费者、主体/权限、外部副作用、迁移、回退和授权条件。
2. 触发词不直接决定级别。结合项目的**代码、数据、流程、关键资源**，记录失败后果、影响范围、发现方式、恢复方式和证据。
3. 逐项检查并按命中的最高级别处理：
   - **非破坏性**：透明扩展，不改变既有行为、数据、安全边界或外部状态。
   - **低**：仅隔离、可丢弃/再生对象，回退已验证，且不碰持久化/共享数据、安全边界或公开契约。
   - **中**：需内部消费者、配置或部署适配，但不命中高风险条件。
   - **高**：删除/覆盖不可丢弃的持久化、共享、用户或生产数据；删除表/列、缩窄字段等可能丢失或使数据不可读的 Schema 变化；权限提升或安全策略放宽；不兼容改变公开 API/共享契约；生产写入、历史覆盖、不可逆外部副作用或可能业务中断。

项目证据可以升级风险，但不得降低已命中的高风险硬门槛。可回滚性不能抵消数据丢失、安全削弱、契约破坏或不可逆副作用。无法证明较低级别条件，且可能为高风险时先暂停补证据。

## 授权门禁

高风险执行前，展示准确的变更元素、环境、影响、迁移、回退及不可回退部分，并取得覆盖这些内容的明确确认；沉默、含糊回复或只确认总体目标都不是授权。

- **确认**：只执行获批范围内的最小动作。
- **修改要求**：更新方案和风险；仍为高风险则重新确认。
- **拒绝**：不执行，给出安全替代或标记阻塞。
- **未回复/含糊**：保持暂停。
- 环境、操作、对象/数据范围、契约、权限、副作用、风险、迁移或回退任一变化，原授权失效并重新分析。

宽迁移采用“扩展 → 分批迁移并验证 → 收缩”。执行后验证实际影响和回退；分级完成且低/中风险方案可执行，或高风险已获有效授权/转为阻塞时退出。
