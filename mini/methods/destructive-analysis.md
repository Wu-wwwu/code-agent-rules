# 破坏性分析

> **触发条件**：涉及数据删除/覆盖、用户或角色权限修改、配置覆盖、有副作用的外部 API 调用、公开 API 请求/响应变化、数据库 Schema 或共享数据契约变化。
> **复用条件**：前一轮已确认影响范围和回退方案、用户许可仍有效且本轮不扩大范围时复用结论；任何范围、契约或风险变化都重新分析并确认。

## 变更分级

| 级别 | 说明 | 要求 |
|------|------|------|
| 非破坏性 | 透明扩展 | 简要记录 |
| 低 | 可兼容影响 | 输出影响清单 |
| 中 | 需适配（返回结构/API 格式变化） | 输出迁移方案 |
| 高 | 数据丢失/安全/业务中断 | 完整迁移+回退方案，用户确认 |

## 事前预测

输出数据/接口/流程/性能/安全破坏预测清单。预扫描对象：
- 本项目：表 / API / 模块 / 共享代码 / 共享配置
- 外部依赖：上游 changelog、release notes 中的 breaking change
- 生成物：迁移文件、锁文件、代码生成产物

## 扩展-收缩迁移模式

宽重构（爆炸半径大）不得一次性切换：

1. **扩展**：新增与旧形态并存
2. **分批迁移**：按包/目录分批切换，每批独立验证
3. **收缩**：确认无残留后删除旧形态

## 累积警告

多个风险项是重新评估信号，不按数量机械折算级别。只有风险之间存在相互作用、共享故障域，或累积后果经证据达到更高级别时才升级。
