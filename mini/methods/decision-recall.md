# 决策回查方法

> **触发条件**：任务涉及历史技术决策、需要确认当前做法是否符合历史约定。

## 回查流程

1. 先按 `methods/project-documents.md` 检查目标项目的 `documents/decision-log.md` 和可选的 `documents/glossary.md`
2. `decision-log.md` 有效时检索其索引表；缺失或仅为示例时，明确说明历史档案覆盖不足，不得推断“没有历史决策”
3. `glossary.md` 有效时用其中同义术语扩展匹配；缺失时改用用户用词、代码标识、Schema、提交历史和当前上下文扩展检索
4. 同一决策可能以不同术语被重提，命中任一同义术语即按命中处理

## 命中结果处理

| 命中结果 | 处理方式 |
|---------|---------|
| 命中冲突 | 输出冲突提示（编号+摘要+冲突点+调和建议）并暂停 |
| 命中 rejected | 输出该决策记录的重提条件；仅在条件满足时重新评估 |
| 不冲突 | 标注关系（补充/增强/替代），继续 |

## 独立缺陷快速路径

常规改动只有同时满足以下条件，才可免于检索 `decision-log`：

1. 目标行为有直接、可验证的依据
2. 修改局限于既有实现接缝
3. 不改变公开 API、Schema、数据格式、业务规则、权限、架构边界
4. 影响范围可由代码引用、调用关系和测试闭环

使用快速路径时，简要记录目标行为依据、修改边界和排除项。

> 文件缺失不是快速路径条件。缺失只表示无法完成持久化档案回查，仍需依据上述条件判断风险，并声明回查覆盖范围。
