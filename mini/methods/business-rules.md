# 业务规则分析

> **触发条件**：涉及金额计算、金融业务逻辑、状态/权限/角色相关决策。
> **跳过条件**：任务不改变金额/状态/权限语义（如纯展示、日志、格式调整），或规则条目已在前序会话中明确确认且未过期。

## 定位规则

1. 定位并引用 `/documents/business-rules.md` 中的对应规则条目
2. 没有可验证依据时，不得推测目标行为

## 边界确认

识别时间、状态、金额、角色等边界条件，选取最多 3 个与当前改动直接相关的关键场景请求确认。

## 实现方式

使用伪代码或流程图明确前置条件、全部判断分支和返回结果。实现时在关键判断处标注对应业务规则编号。

## 决策框架

当需要在多个方案中选择时：

| 步骤 | 内容 |
|------|------|
| 1. 识别冲突 | 明确冲突点（技术、业务、资源） |
| 2. 方案对比 | ≥2 方案，各 ≥2 优缺点 |
| 3. 推荐方案 | 给出推荐理由 |
| 4. 标注影响范围 | 涉及的模块、数据、测试 |

## 决策记录

决策记录在 `/documents/decision-log.md`，包含：编号、日期、标题、状态、冲突点、背景、方案对比、最终选择、影响范围、重提条件。

新建决策条件（三者同时满足）：难以撤销、无上下文会惊讶、存在真实权衡。任一不满足则不建档。

## 决策优先级

1. 数据安全/正确性 > 性能
2. 可维护性 > 代码简洁性
3. 显式 > 隐式
4. 内部一致性 > 外部最佳实践
