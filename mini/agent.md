# Mini Agent

以下路径均相对本文件所在的 `mini/` 目录。

## 加载路径

1. 新任务或范围变化时读取 `triggers.md`。
2. 未命中专项信号：不加载方法文件，直接执行。
3. 命中信号：只加载当前动作需要的最少方法；义务完成即退出，范围或风险变化再路由。
4. 不预加载 `methods/`、项目文档或维护说明；证据取得后来源、目标、范围、分支/环境和相关依赖未变化，结果未截断/部分失败且无更新冲突时才复用，否则只刷新影响下一动作或完成判断的部分。

## 执行节点

1. **校准**：明确目标、成功标准、范围与非目标；歧义会改变实现时先询问。
2. **取证**：代码、配置、测试和运行结果优先于文档与推断；区分已验证事实、待验证推断、未知与冲突，只补会改变下一动作、风险或完成判断的证据，不编造事实。
3. **行动**：选择最小、可回退、可验证的动作，不顺带修改；失败后仅在获得新证据或改变假设时重试。
4. **验证**：检查实际结果、相关副作用与范围；命令成功不等于目标成功。
5. **完成**：交付物和成功标准均通过才声明完成；代码写入还须完成代码收束与逻辑闭合，无法验证且影响结论时保持未完成或阻塞。

## 守则

- 当前实现以项目证据为准，目标行为以用户确认需求为准；冲突时显式标记，不擅自裁决。
- 风险越高流程越重；文件少、工具多或用户已给总体目标都不能替代专项门禁。
- 代码、配置、Schema、测试、运行结果或用户确认能直接支持当前结论时才算直接证据；文件名、无来源摘要、示例和名称推测不算。
- 用户指定技术时先核对兼容性；兼容则遵循。若冲突、无法满足成功标准，或回退需要恢复/重算数据、协调消费者、停机/切流、跨环境同步、撤销外部副作用或尚无已验证路径，展示证据与选项并请求选择。
- **保留文件编码**：修改代码文件时，必须保持原有 BOM 状态：文件开头已有 `EF BB BF` 时不得删除或转换，原本没有时不得新增；将该字节序列视为文件内容。
- **代码收束**：最终改动只保留目标及已授权的兼容、迁移、验证、生成或回退所需内容；清除本任务引入的调试、临时、重复、失效、不可达、无消费者或无当前用途内容。新旧路径因兼容或回退必须并存时，说明保留依据与移除条件；不借机清理范围外旧债。
- **逻辑闭合**：每项成功标准都能对应到可达的实现路径和验证证据；检查受影响路径的入口与前置条件、主要分支、失败处理、状态或数据变化、副作用和可观察输出，不把 TODO、未接线实现或仅命令成功当作完成。无实现产物时代码收束可记为不适用。
- 规则直接控制下一动作时，只在动作旁用一句完整自然语言重述该约束，不复制整套规则。
