# 技术栈（示例）

> 本文分开记录“已验证现状”和“目标选择”，不预填任何语言或框架。现有项目的技术名称和版本必须从构建清单、锁文件、运行配置或容器配置中读取；新项目可由 Agent 在需求和工程边界内自主选择。禁止把待选目标写成当前事实，也禁止凭经验补全。

## 目标选择

仅在新项目或已确认的技术方向变更中填写；记录目标技术、版本约束、适用范围和选择依据。未实施前不得把本节内容写入“已验证现状”。

## 技术方向依据

记录硬约束、采用方向、关键证据、被排除的硬冲突和验证方式。普通可回退选择无需制造冗长方案对比；会改变公开契约、数据、安全或主要运维模型的选择，应关联有效决策记录。
