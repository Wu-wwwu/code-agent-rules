# 数据实体与表示变换

> **触发**：从代码/Schema/表/序列化格式识别实体、归并表示、推导关系或说明变换；**轻量**：单个已知构件局部查阅不建模型，需归并/推导/追踪变换时才走完整方法。

## 概念隔离

- **代码构件**：类型、DTO、消息、参数、Schema、表等具体表示
- **数据实体**：跨表示追踪同一组数据的中性分析概念，不要求新增领域对象
- **现实对象**：现实领域知识和概念

名称只用于检索。无用户说明、有效资料、代码行为、约束或测试证据时：不把数据实体等同于同名现实对象，不用行业常识补全字段/关系/生命周期/规则，无关现实含义抽离为中性标签。

## 抽取与关联

1. 从类型、字段、参数、返回值、Schema、表、查询、映射配置、测试提取候选构件
2. 记录标识、字段、键、约束、来源位置、输入输出；名称相似不证明同一实体
3. 仅依据类型引用、字段包含、键约束、Schema 引用、ORM/序列化映射、查询 JOIN、函数输入输出、显式转换、测试或用户确认建立关系
4. 需跨表示追踪时分配中性标识（如 `DE-001`），记录各表示及关系证据；证据不足则分开并标记待确认

## 创建与变换流程

按实际存在环节输出：`来源/创建 → 校验 → 查询/补全 → 变换 → 持久化/传递 → 输出`

每节点记录：执行构件、输入/输出表示、字段增删/重命名/格式变化、约束变化、实体关系、证据位置。名称相同不代表没有变换，名称不同也不证明是不同实体。

## 最小输出

```markdown
### DE-001：<中性数据名称>
- 表示：`Request` → `Model` → `table_name` → `Response`
- 已证实关系：<来源构件> --<关系>--> <目标构件>（证据）
- 流程：创建 → 校验 → 变换 → 写入 → 输出
- 字段变化：<输入字段> → <处理> → <输出字段>
- 语义边界：仅表示代码中的数据；现实含义未确认/当前任务不需要
- 未知项：<待确认内容>
```
