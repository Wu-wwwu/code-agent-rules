# 决策回查方法

> **触发**：需要保存或更新选择依据，当前依据缺失且影响判断、证据冲突、拟改变仍有效的重要约束，或用户明确要求回查。当前方案及关联依据足够且无冲突时跳过历史检索，不限于局部缺陷。

## 选择依据与独立记录

选择依据是当前技术方案、数据结构和流程说明的辅助证据。只保留对未来修改有影响且无法从当前实现或有效契约直接推导的信息：当前选择及适用范围、成立前提与证据、仍然有效的关键取舍、重新评估或失效条件。同一依据只维护一个主要位置，其他文档引用；不把用户原话、确认过程、日期、历史背景或方案确认写成已验证实现。

记录内容区分当前事实、当前约束、待验证推断和历史/审计材料。历史和审计材料仅作待核实依据，不能覆盖当前代码、配置、测试、运行结果或当前有效授权；过期或冲突内容先核对，不直接作为现状或授权。

### 新建决策条件

只有同时满足以下条件才新建独立决策记录：撤销需要协调或恢复；不能从当前有效证据直接推导；至少两个真实可行方向后果不同；有未来复用价值且跨模块或跨文档需要统一引用，相关当前说明无法就地充分承载。缺失该依据会造成误改有效约束、误判兼容边界或重复代价较高的调查。任一不满足则就地保存必要依据或只在任务结果说明，不为建档制造选择。独立记录至少保留当前选择、适用范围、当前说明链接、前提、证据和重评/失效条件；状态、日期、替代关系或否决条件仅在生命周期、审计留存或当前判断需要时保留。

## 回查流程

1. 按 `methods/project-documents.md` 检查当前方案、数据或流程说明及关联依据，先核对当前实现证据；足够且无冲突则继续。
2. 只有触发条件要求追溯时，按相关引用、任务描述中的用词、代码标识、Schema 和已验证同义术语定向查日志、提交或归档，不扫描全部历史；档案缺失只表示覆盖不足，不能推断没有历史决策。
3. 命中仅是线索：核对适用范围、成立前提和当前依赖，不凭关键词或 active/rejected 状态认定约束仍有效。
4. 依据足以支持动作或剩余未知不影响动作时退出；关键未知影响正确性或权限且无法消除时报告具体阻塞。

## 命中结果处理

| 命中结果 | 处理方式 |
|---------|---------|
| 当前有效约束冲突 | 与当前有效授权、业务规则、外部契约或硬性要求冲突时暂停受影响执行并请求相应确认；历史冲突本身不自动暂停 |
| 命中 rejected | 否决前提仍成立且无新证据时不重复同一提案；前提、需求或成本已变化，或重提条件满足时可重新评估并说明证据，不形成永久禁令 |
| 已失效且无当前依赖 | 不阻止当前方案，按生命周期退出默认查询 |
| 不冲突 | 需要时标注补充、增强或替代关系并继续 |

## 独立缺陷快速路径

以下条件可直接证明局部缺陷无需历史检索，但不是免检索的唯一情形；其他任务按实际触发判断：

1. 目标行为有直接、可验证的依据
2. 修改局限于既有实现接缝
3. 不改变公开 API、Schema、数据格式、业务规则、权限、架构边界
4. 影响范围可由代码引用、调用关系和测试闭环

走快速路径时仅说明目标行为依据和修改边界，不因此建档；受影响文档仍按实际变化对齐。

文件缺失不证明没有历史约束；是否需要追溯取决于当前证据缺口，不因档案缺失扫描全部历史。风险、授权与验证要求始终适用。

## 依据生命周期

只在当前变更触及某项依据时复核，不逐任务扫描历史。仍有效的就地保留；已替代但仍影响兼容、迁移、恢复或审计留存的，保留必要旧依据、替代关系和移除条件。代码已修改不证明依赖已消失。

已失效且无当前依赖的退出当前说明和默认查询，历史解释按需追溯；查询价值与留存义务分别判断。重复、临时或无复用价值的内容在授权范围内合并或清理并修复引用；确认无兼容、迁移、恢复和审计留存义务后才移除。需历史恢复时先确认可定位的版本或归档，不假定未提交记录已保存，不改写版本历史或清理无关记录。
