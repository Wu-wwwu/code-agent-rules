# 多 Agent 协作方法

> **触发**：子任务有独立完成标准、不依赖尚未产生的前序结果，且适合只读并行、隔离且有唯一所有者的写入，或需要独立专业证据；主 Agent 一次工具调用/一个局部动作可完成、必须串行等待、同一文件/共享状态无法划分所有权、需要主 Agent 作授权/业务/不可逆选择时保持单 Agent。

主 Agent 只投影与子任务正确性有关的上下文，不复制整个会话；也不得为省 token 丢失兼容要求、权限要求、依赖或共享资源所有权。

## 任务包契约（委派前至少传递）

```markdown
## 任务包

### 目标
<一句话描述>

### 范围
- 允许读取：<路径列表>
- 允许写入：<路径列表（通常为空）>
- 非目标/禁止操作：<列表>

### 完成标准
<可验证的条件>

### 已知事实
<已验证的事实及证据位置>

### 推断与未知
<待验证推断、未知、冲突及所需证据>

### 约束与依赖
<接口/数据契约、兼容要求、风险要求、前置子任务、共享资源所有者与合并顺序>

### 验证
<命令、观察点或验收证据>

### 返回格式
- 已验证事实：<列表>
- 推断与未知：<列表>
- 采取的动作：<列表>
- 修改范围与证据位置：<列表>
- 验证结果：<通过/失败/无法验证>
- 残余风险：<列表>
- 建议下一步：<描述>
```

## 并行与写入规则

- 只读调查可并行
- 共享工作区默认单写者模型
- 只有能证明独立工作区并明确所有权、合并顺序时才并行写入
- 子 Agent 默认不得继续委派

## 结果验收（主 Agent 必须）

1. 检查结果是否满足任务包
2. 复核会影响全局结论、写入安全、共享契约或跨子任务接口的事实，并检查完整 diff 与相关测试；其他事实可按风险抽样但标注未复核范围
3. 检查重复修改、冲突假设、遗漏影响
4. 只有全局成功标准通过后才声明完成

验收标记为 `accepted` / `needs-verification` / `needs-rework` / `blocked`；只有 `accepted` 的事实与改动可并入全局状态。子任务成功不等于全局完成；任务变成串行链、写入边界重叠，或协调与复核步骤不再少于主 Agent 直接完成所需步骤时停止拆分并恢复单 Agent。
