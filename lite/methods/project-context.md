# 项目上下文与实现路径方法

> **触发**：新增功能/计划/跨模块/上下文恢复/用户改变目标或边界与实现路径不清；**目标**：最小项目认知，不建无关地图；**轻量**：简单局部且已有新鲜完整上下文时不构造上下文包。

构造的是当前任务所需的环境切片，不是完整项目模型。委派时再按子任务目标、边界、依赖、风险和验收投影为最小任务包，并保留关键证据位置。

## 上下文来源（按需选择，不全读）

1. 用户本轮确认的目标、约束、成功标准、非目标
2. 代码、配置、Schema、测试、日志、运行结果
3. 构建清单、入口、依赖引用、版本历史、部署配置
4. 目标项目中有效的 `documents/project-doc.md`、`architecture.md`、`tech-stack.md`、`data-flow.md`、`business-rules.md`、`decision-log.md`、`coding-standards.md`、`glossary.md`
5. 基于以上证据的待验证推断

读取或初始化项目文档前遵循 `methods/project-documents.md`；示例/占位/无来源摘要/与实现冲突的内容不得作为项目事实。

## 最小任务上下文包（简单任务内部维护，不必完整输出）

| 字段 | 内容 | 最低证据要求 |
|------|------|--------------|
| 用户目标与成功标准 | 最终结果、可观察完成条件 | 用户输入或已确认验收 |
| 非目标与范围 | 不做什么、读写边界、兼容要求 | 用户输入、仓库边界或现有契约 |
| 项目目标关联 | 任务服务或冲突的项目目标/能力 | 有效项目说明、README、用户确认或可验证行为 |
| 当前实现事实 | 与任务直接相关的入口、模块、配置、行为 | 代码、配置、测试或运行结果 |
| 功能实现路径 | 入口→核心模块→数据/外部依赖→输出→测试/观察点 | 调用、引用、映射、配置和测试证据 |
| 当前约束 | 架构、业务、安全、兼容、技术、作用域 | 对应事实或有效决策来源 |
| 未知与冲突 | 未验证、证据不一致、需用户裁决项 | 明确标记，不伪装为事实 |
| 下一动作与验证 | 最小动作、成功/失败信号、验证方式 | 能推进目标或降低关键不确定性 |

不能说明某字段如何影响当前动作时，不为填表继续调查。

## 构造步骤

1. **校准**：确认目标、成功标准、范围、非目标；关键歧义会改变实现时先询问
2. **复用**：会话内新鲜、直接、同范围证据优先；缺失/过期/冲突/范围变化才补读
3. **定位关联**：任务属于哪个功能/能力，或明确与项目目标无关；不凭文件名推产品语义
4. **追踪路径**：从用户可观察入口沿调用/数据/配置/依赖追到输出与验证接缝；到稳定边界即停，不扫无关区
5. **提取约束**：只保留会否决方案、限制写入、改变风险或影响验收的约束；必要时加载对应专项方法
6. **形成计划**：每步可追溯到目标、路径节点或验证缺口；不把"读所有文档"当默认步骤
7. **决策点共址**：在受约束的计划/工具调用/修改点旁，用完整自然语言重述最关键约束
8. **验证刷新**：结果与上下文不一致时更新事实、未知、下一步，不为旧计划忽略新证据

## 不同任务的最小扩展

- **新功能/计划**：项目目标关联、功能边界、入口到输出路径、架构/技术约束、测试接缝
- **Bug**：预期行为、实际行为、复现入口、受影响路径、最近变化、可观察点；复杂 Bug 另加载 `methods/bug-diagnosis.md`
- **跨模块**：模块职责、依赖方向、共享契约、数据/状态传播、稳定边界
- **技术选择**：现状、硬约束、候选影响、验证方式；存在真实方案空间时加载 `methods/technology-selection.md`
- **历史约束**：仅当当前选择可能重复或冲突历史决策时加载 `methods/decision-recall.md`

## 写回长期项目记忆（仅同时满足）

1. 内容已由代码/配置/测试/运行结果/用户确认验证
2. 后续任务有跨会话复用价值
3. 非一次性步骤、临时假设、未清理调试信息
4. 写入在本次授权范围，不覆盖项目已有自定义结构

写回后回读核对来源；推断标记"待确认"；实现变化使旧记录过期时更新或标记冲突，不静默保留矛盾事实。

## 停止条件（满足即可退出，恢复 agent.md 普通路径）

- 目标、范围、成功标准已足以行动
- 已确定本轮实现路径和约束
- 下一动作有明确预期与验证方式
- 剩余未知不影响当前动作正确性，或已转为明确阻塞/待确认项

不为"环境完整"持续扩展上下文；上下文价值以是否改善当前决策和验证为准。
