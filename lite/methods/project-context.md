# 项目上下文与实现路径方法

> **触发**：新增功能/计划/跨模块/上下文恢复/有效任务目标或边界变化/实现路径不清；**目标**：只建立会改变动作、风险或验收的项目认知；**轻量**：行为未越过公开契约、Schema、共享配置/状态、安全权限、生产副作用或新增消费者边界，且已有可复用的同范围上下文时不构造上下文包。

构造的是当前任务所需的环境切片，不是完整项目模型。委派时再按子任务目标、边界、依赖、风险和验收投影为最小任务包，并保留关键证据位置。

## 上下文来源（按需选择，不全读）

1. 当前有效任务要求中的目标、约束、成功标准与非目标；补充描述和引用材料另作待验证线索
2. 代码、配置、Schema、测试、日志、运行结果
3. 构建清单、入口、依赖引用、版本历史、部署配置
4. 目标项目中有效的 `documents/project-doc.md`、`architecture.md`、`tech-stack.md`、`data-flow.md`、`business-rules.md`、`decision-log.md`、`coding-standards.md`、`glossary.md`
5. 基于以上证据的待验证推断

实际读写或初始化 `documents/*.md` 前遵循 `methods/project-documents.md`；示例/占位/无来源摘要不得作为项目事实，与实现冲突的条目先分类核验，不自动判定规范过期。

## 最小任务上下文包（简单任务内部维护，不必完整输出）

| 字段 | 内容 | 最低证据要求 |
|------|------|--------------|
| 任务目标与成功标准 | 最终结果、可观察完成条件 | 当前有效任务要求或已确认验收；这是目标依据，不是当前实现事实 |
| 非目标与范围 | 不做什么、读写边界、兼容要求 | 有效任务要求、仓库边界或现有契约；补充描述不自动成为约束、事实或授权 |
| 项目目标关联 | 任务服务或冲突的项目目标/能力 | 有效项目说明、README 或可验证行为；用户确认仅作为目标依据 |
| 当前实现事实 | 与任务直接相关的入口、模块、配置、行为 | 代码、配置、测试或运行结果 |
| 功能实现路径 | 入口→核心模块→数据/外部依赖→输出→测试/观察点 | 调用、引用、映射、配置和测试证据 |
| 当前约束 | 架构、业务、安全、兼容、技术、作用域 | 对应事实或有效决策来源 |
| 未知与冲突 | 未验证、证据不一致、需裁决项 | 明确标记，不伪装为事实 |
| 下一动作与验证 | 最小动作、成功/失败信号、验证方式 | 能推进目标或降低关键不确定性 |

不能说明某字段如何影响当前动作时，不为填表继续调查。

## 需求转检索与探索纠偏

- **需求转检索目标**：从当前任务的目标、明确要求和补充描述中提取可观察行为、约束与验收，区分明确要求、待验证描述和推定验收，转为入口、数据、规则和验证接缝（测试入口、接口断言或运行观察点）。描述中的术语仅作检索线索；对应关系以符号、引用、Schema、配置或测试为证，名称相似不证明对应。
- **锚点与纠偏**：关键探索方向明确依据和预期命中，不要求逐次播报；未命中先核对检索范围和必要的命名变体，假设被证伪或仍无支持证据时切换另一类锚点（入口/路由、数据/Schema、测试、日志/错误信息、配置、已验证术语映射），避免沿同一假设无依据地反复扩搜。
- **复用与新增**：新建前检查可复用或可扩展的现有实现；在已检查范围内未发现适用实现时，说明检索范围、证据、未覆盖区域及新增理由，再在授权内新增。不把未命中断言为全局“不存在”，不要求穷尽无关路径。
- **文档按条盘点**：只核对任务相关条目，标记为一致、过期/冲突、缺失或无法验证，不整份重建或丢弃仍一致的内容。描述性条目按已验证事实更新；规范性条目与实现冲突时，先据有效契约或用户确认判定修代码还是修文档，不以当前实现或现有测试自动覆盖业务规则、验收要求或外部契约。
- **未知分流**：代码、配置、测试或运行结果可自主确认且影响动作、风险或验收的先取证；目标、范围、验收、业务语义或外部契约存在需裁决的歧义，或缺少无法自行获取且影响后续动作的关键信息、权限或操作授权时，再请求必要澄清、资料或授权，注明受影响动作和已有证据。不影响当前动作的未知标注后继续，只暂停受阻动作。
- **导航经验写回**：任务文档维护覆盖受影响的行为、契约或验收条目，不限于导航信息；另按需沉淀已验证、可复用的导航事实（术语到代码锚点、运行/测试命令、项目特有约定），附来源与失效条件，不记录探索过程。实际读写 `documents/*.md` 时遵循 `methods/project-documents.md`；仅需最小模板时加载 `methods/templates.md`，不为补齐目录创建文档，写回仍需满足授权与复用条件。

## 构造步骤

1. **校准**：确认目标、成功标准、范围、非目标；关键歧义先核对有效要求与现有证据，仍影响动作且无法消除时再请求必要澄清
2. **复用**：仅当证据取得后来源、目标、范围、分支/环境和相关依赖未变化，结果未截断/部分失败且无更新冲突时复用；否则只补影响动作、风险或验收的部分
3. **定位关联**：任务属于哪个功能/能力，或明确与项目目标无关；不凭文件名推产品语义
4. **追踪路径**：从用户可观察入口沿调用/数据/配置/依赖追到输出与验证接缝；追到本任务不修改、契约明确且后续影响与成功标准无关的稳定边界即停，不扫无关区
5. **提取约束**：只保留会否决方案、限制写入、改变风险或影响验收的约束；必要时加载对应专项方法
6. **形成计划**：每步可追溯到目标、路径节点或验证缺口；不把"读所有文档"当默认步骤
7. **决策点共址**：在受约束的计划/工具调用/修改点旁，用完整自然语言重述最关键约束
8. **验证刷新**：结果与上下文不一致时更新事实、未知、下一步，不为旧计划忽略新证据

## 最小充分模型

新增入口、数据表示变化、事务或外部副作用需要推导，或改动将改变既有执行顺序、状态转换或副作用时机时同样适用本方法；局部且直接可验证的修改不要求额外建模。

建模结论描述系统当前的职责、约束与行为，实现路径描述如何修改；两者分开维护，不用实现便利性倒推领域模型。模型与实现证据冲突时以实现为准并标记，目标行为仍以有效需求和业务规则为准。

- 从用户可观察路径确认改动点、关键不变量、验证接缝，以及必要的数据转换和失败处理；三要素足以支持当前动作即转入实现，不为完整地图扩展模型。新证据使前提失效时只重开受影响部分。
- 改动会改变执行顺序、状态转换或副作用时机时，关键不变量必须显式覆盖：受影响调用链（入口→关键节点→出口）、状态转换（状态集合、允许与非法转换）、步骤间顺序依赖，以及副作用（DB/缓存/消息/外部调用/通知）相对事务边界的位置；未受影响的维度不要求枚举。
- 按实际代码职责选择可组合的表示：数据访问关注数据/存储结构，业务处理关注模型/不变量，算法关注数据结构/复杂度，边界编排关注契约/映射/副作用；不依据文件名或预设分层强行套用。
- 内存变换关注进程内表示、可变性、生命周期、不变量和计算；持久化处理关注存储模型、事务、提交可见性、并发、幂等、恢复和迁移。序列化、缓存、队列等边界单独验证，不自动拆成目录或类层次。
- 编码方向按问题目标、职责边界、数据表示、变换过程、状态生命周期、控制流、副作用和验证接缝推导；设计模式、编程范式和分层结构只是可选表达方式，不能在证据不足时作为实现起点。
- 涉及数据保留或变换时，按实际路径区分内存生命周期、持久化时机、缓存生命周期、消息发送/确认时机以及外部调用/通知时机；只在某一边界影响当前动作、正确性、恢复或验收时建模该边界。
- 创建模型只为解释当前职责、约束、变换、生命周期或验证边界；模型不能改变当前动作或完成判断时，不继续扩展模型，也不自动将模型写入项目文档。
- 状态按实际需要区分业务、数据有效性、执行控制、持久化一致性、并发版本和外部副作用，不把不同维度混为一个状态字段。

## 不同任务的最小扩展

- **新功能/计划**：项目目标关联、功能边界、入口到输出路径、架构/技术约束、测试接缝
- **Bug**：预期行为、实际行为、复现入口、受影响路径、最近变化、可观察点；复杂 Bug 另加载 `methods/bug-diagnosis.md`
- **跨模块**：模块职责、依赖方向、共享契约、数据/状态传播、稳定边界
- **技术选择**：现状、硬约束、候选影响、验证方式；存在真实方案空间时加载 `methods/technology-selection.md`
- **选择依据**：先看当前方案及关联依据；需记录、依据缺失且影响判断、证据冲突或拟改变有效约束时加载 `methods/decision-recall.md`，不默认检索日志

## 写回长期项目记忆（仅同时满足）

以下条件用于新增记忆；已有文档受任务影响的条目仍须按上述事实与规范边界维护，并满足证据与授权要求，不以复用价值为由跳过。

1. 内容已由代码/配置/测试/运行结果验证；用户确认仅可补充目标、约束或业务语义，不单独证明当前实现事实
2. 后续任务有跨会话复用价值
3. 非一次性步骤、临时假设、未清理调试信息
4. 写入在本次授权范围，不覆盖项目已有自定义结构

写回后回读核对来源；推断标记"待确认"；实现变化使旧记录过期时更新或标记冲突，不静默保留矛盾事实。

## 停止条件（满足即可退出，恢复 agent.md 普通路径）

- 目标、范围、成功标准已足以行动
- 已确定本轮实现路径和约束
- 下一动作有明确预期与验证方式
- 剩余未知不影响当前动作正确性，或已转为明确阻塞/待确认项

不为"环境完整"持续扩展上下文；上下文价值以是否改善当前决策和验证为准。
