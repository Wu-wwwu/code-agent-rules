# 破坏性分析

## 变更分级

按实际后果而不是关键词、文件数或代码行数分级；命中多项时取最高级，无法证明较低级别全部条件时不得降级：

| 级别 | 客观条件 | 最低动作 |
|------|----------|----------|
| 非破坏性 | 仅透明扩展；不改变既有消费者行为、已有数据、安全边界或外部状态 | 记录影响并验证兼容性 |
| 低 | 只影响隔离、可丢弃或可再生对象；回退已验证；不涉及持久化/共享数据、安全边界或公开契约 | 输出影响清单并验证回退 |
| 中 | 需要内部消费者、配置、部署或生成物适配，但不命中高风险条件 | 输出分步迁移、验证与回退方案；实施方案、范围和停止条件确认后写入 |
| 高 | 删除/覆盖不可丢弃的持久化、共享、用户或生产数据；删除表/列、缩窄字段等可能丢失或使数据不可读的 Schema 变化；权限提升或安全策略放宽；不兼容改变公开 API/共享契约；生产写入、历史覆盖、不可逆外部副作用或可能业务中断 | 输出准确影响清单及迁移与回退方案，取得覆盖具体变更元素的明确确认后再执行 |

可回滚性只能改善回退方案，不能抵消数据丢失、安全削弱、公开契约破坏或不可逆外部副作用。项目证据可以升级风险，但不得降低已命中的高风险条件；信息不足且可能命中高风险时先暂停补证据。

## 事前预测
需求审查、影响预扫描，先列出变更元素：目标环境、操作、对象/数据范围或数量级、契约及消费者、主体/权限、外部副作用、迁移、回退和授权条件。输出数据/接口/流程/性能/安全破坏预测清单。预扫描对象：
- 本项目：表 / API / 模块 / 共享代码 / 共享配置；
- 外部依赖：上游 changelog、release notes 中的 breaking change 与弃用到期项；
- 生成物：迁移文件（migration）、锁文件（lock）、代码生成产物——常被遗漏但同样承载旧形态。

预扫描应包含可能被遗漏的隐式生产者：生成器、编译器或格式化器升级后产生的代码、配置、Schema、快照、资源清单和部署产物。若不能直接修改或稳定重现生成物，说明工具链版本、生成命令、所有权和验证缺口，不把源文件修改等同于产物已更新。

## 工具链与作用域边界

- 执行前确定规则文件、仓库配置、用户级配置、全局配置和生成工具各自的作用域与优先级；只修改任务授权且实际生效的最小层级。
- 不把“在某目录执行命令”自动解释为允许修改用户级或全局状态；安装、升级、重配置工具前先确认项目本地方案是否足够。
- 依赖或工具链变更同时检查声明文件、锁文件、生成物、CI/CD、容器和部署环境，防止只更新其中一侧。
- 生成或迁移动作必须记录工具版本、命令、输入范围和产物位置；同一版本、输入与配置应能重现产物。无法重现或无权验证时列为验证缺口；命令退出成功不证明产物完整或目标环境会采用它。

## 事中检测
自审：共享状态改动？外部依赖？返回值误解？意图核查：一致性、边界遗漏。

## 授权门禁

- 中风险写入前，展示实施方案、修改范围、分步验证与停止条件并取得确认；用户原请求已明确覆盖这些内容时可引用该授权。
- 高风险写入前，必须展示目标环境、操作、对象/数据范围、契约与消费者、权限、外部副作用、迁移步骤、回退方式和不可回退部分，并取得覆盖这些内容的明确确认。沉默、含糊回复或只确认总体目标都不是授权。
- 用户确认后只执行获批范围；修改要求导致任一变更元素或风险变化时重新分析，仍为高风险则重新确认；拒绝或未回复时保持暂停并提供安全替代或阻塞说明。

## 事后核验
逐条对比预测与实际影响。预测遗漏和误报输出到任务报告。

## 记录边界
- **变更审计记录**：中/高风险、跨会话迁移或需要长期回查的变更，写入 `/documents/decision-log.md`「变更审计记录」；至少记录变更元素、授权、实际影响、验证结果和残余风险。低风险仅在项目约定要求或后续任务需要复用时记录。
- 审计记录只保留可核对的变更事实、适用授权、实际影响、验证结果和残余风险；不复制用户原话、过程流水、主观判断或无条件推测。日期、记录编号和操作者仅在审计、追责或事件关联需要时保留；审计材料属于历史/审计证据，不得覆盖当前实现事实或当前授权。
- **决策记录**：只有同时满足 `business-analysis.md`「新建决策条件」的真实方案选择，才写入“决策记录”区。破坏性审计记录本身不等于技术决策，也不放宽决策记录的建档条件。
- 两类记录可以在同一条变更中同时出现，但分别按各自条件记录；去重合并，同根因不重复建条目。

### 扩展-收缩迁移模式
当变更需要多个消费者、包/目录、部署单元、数据批次或环境协调时，不得一次性切换：
1. **扩展**：新增与旧形态并存
2. **分批迁移**：按消费者、包/目录、数据批次、部署单元或环境分批切换，每批独立验证数量、内容和错误
3. **切换**：按预先定义的成功指标、错误阈值和停止条件改变主路径
4. **收缩**：确认无残留消费者、旧数据或回退需求后删除旧形态

迁移与回退方案至少包含：变更元素与所有者、前后不变量、批次边界、兼容策略、计数/校验和或等价内容校验、错误阈值、停止条件、监控观察点、代码/数据/流量回退步骤和不可逆部分。缺任一影响正确性或恢复能力的字段时，不得称为完整方案。

## 累积警告
多个风险项是重新评估信号，不按数量机械折算级别。只有风险之间存在相互作用、共享故障域，或累积后果经证据达到更高级别时才升级；高破坏性必须输出完整迁移与回退方案。
