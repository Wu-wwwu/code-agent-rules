# 破坏性分析

## 变更分级
- 非破坏性：透明扩展
- 低：可兼容影响
- 中：需适配（返回结构/API 格式变化）
- 高：数据丢失/安全/业务中断

## 事前预测
需求审查、影响预扫描，输出数据/接口/流程/性能/安全破坏预测清单。预扫描对象：
- 本项目：表 / API / 模块 / 共享代码 / 共享配置；
- 外部依赖：上游 changelog、release notes 中的 breaking change 与弃用到期项；
- 生成物：迁移文件（migration）、锁文件（lock）、代码生成产物——常被遗漏但同样承载旧形态。

## 事中检测
自审：共享状态改动？外部依赖？返回值误解？意图核查：一致性、边界遗漏。

## 破坏性能力标记
```
// [破坏性能力] 类型：数据删除 / 表结构变更 / 共享配置 / 执行顺序 / 全局状态
// 风险：误用后果
// 防护：前置条件或使用限制
```

## 事后核验
逐条对比预测与实际影响。预测遗漏和误报输出到任务报告。

## 破坏性日志
写入 `decision-log.md` 破坏性变更区，按场景和级别选择性记录。去重合并，同根因不重复建条目。

### 扩展-收缩迁移模式
宽重构（爆炸半径大）不得一次性切换：
1. **扩展**：新增与旧形态并存
2. **分批迁移**：按包/目录分批切换，每批独立验证
3. **收缩**：确认无残留后删除旧形态

## 累积警告
以下折算比为启发式默认值，有项目证据时以证据为准：≥3 低 → 视同 1 中；≥2 中 → 视同 1 高；高破坏性必须输出完整迁移+回退方案。
