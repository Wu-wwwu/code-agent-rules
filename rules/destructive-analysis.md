# 破坏性分析

## 变更分级
- 非破坏性：透明扩展
- 低：可兼容影响
- 中：需适配（返回结构/API 格式变化）
- 高：数据丢失/安全/业务中断

## 事前预测
需求审查、影响预扫描，输出数据/接口/流程/性能/安全破坏预测清单。预扫描对象：
- 本项目：表 / API / 模块 / 共享代码 / 共享配置；
- 外部依赖：上游 changelog、release notes 中的 breaking change 与弃用到期项；
- 生成物：迁移文件（migration）、锁文件（lock）、代码生成产物——常被遗漏但同样承载旧形态。

预扫描应包含可能被遗漏的隐式生产者：生成器、编译器或格式化器升级后产生的代码、配置、Schema、快照、资源清单和部署产物。若 Agent 不能直接修改或稳定重现生成物，说明工具链版本、生成命令、所有权和验证缺口，不把源文件修改等同于产物已更新。

## 工具链与作用域边界

- 执行前确定规则文件、仓库配置、用户级配置、全局配置和生成工具各自的作用域与优先级；只修改任务授权且实际生效的最小层级。
- 不把“在某目录执行命令”自动解释为允许修改用户级或全局状态；安装、升级、重配置工具前先确认项目本地方案是否足够。
- 依赖或工具链变更同时检查声明文件、锁文件、生成物、CI/CD、容器和部署环境，防止只更新其中一侧。
- 生成或迁移动作应尽量可重复、可审查并记录命令与版本；命令退出成功不证明产物完整或目标环境会采用它。

## 事中检测
自审：共享状态改动？外部依赖？返回值误解？意图核查：一致性、边界遗漏。

## 破坏性能力标记
```
// [破坏性能力] 类型：数据删除 / 表结构变更 / 共享配置 / 执行顺序 / 全局状态
// 风险：误用后果
// 防护：前置条件或使用限制
```

## 事后核验
逐条对比预测与实际影响。预测遗漏和误报输出到任务报告。

## 破坏性日志
写入 `decision-log.md` 破坏性变更区，按场景和级别选择性记录。去重合并，同根因不重复建条目。

### 扩展-收缩迁移模式
宽重构（爆炸半径大）不得一次性切换：
1. **扩展**：新增与旧形态并存
2. **分批迁移**：按包/目录分批切换，每批独立验证
3. **收缩**：确认无残留后删除旧形态

## 累积警告
多个风险项是重新评估信号，不按数量机械折算级别。只有风险之间存在相互作用、共享故障域，或累积后果经证据达到更高级别时才升级；高破坏性必须输出完整迁移与回退方案。
