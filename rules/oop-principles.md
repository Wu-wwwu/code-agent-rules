# 编程范式与编码规范

## 1. 领域驱动设计核心

- **统一语言**：代码命名与业务术语一致，代码跟随语言变化。
- **限界上下文**：同一术语不同含义分上下文，通过接口通信，不共享数据表。
- **实体 vs 值对象**：实体有唯一 ID（可变），值对象无 ID（必须不可变）。
- **聚合与聚合根**：聚合定义一致性边界，外部仅通过聚合根访问。一次事务只改一个聚合实例，聚合间引用用 ID。
- **领域服务**：跨聚合逻辑，无状态，方法名来自业务语言。优先放实体内避免贫血模型。
- **资源库**：每聚合最多一个，接口在领域层，实现在基础设施层。

## 2. OOP 核心

- **单一职责**：每个函数/模块仅一个变化原因。函数名不含"和""与"。
- **命名**：类名名词短语，方法名动词短语，布尔值 Is/Has/Can。
- **反模式**：上帝类、深层嵌套(>3)、魔法数字、重复代码、过早优化、贫血模型。
- **深模块**：接口小而行为多。接缝是可不修改此处而改变行为的位置。
- **测试**：打在预定接缝上，验证行为而非实现。禁止同义反复、实现耦合、水平切片。

## 3. AOP 核心

- **横切关注点**：日志、异常、认证、授权、验证、事务。业务代码不应感知切面。
- **顺序**：日志(最外) → 异常 → 认证 → 授权 → 验证 → 事务(最内)。
- **边界**：切面不包含业务逻辑，通过共享上下文通信。

## 4. FP 核心

- **纯函数**：相同输入相同输出，无副作用。
- **不可变数据**：修改返回新对象。
- **声明式**：优先 map/filter/reduce，避免显式循环和可变累积。
- **函数组合**：纯函数串联成管道。

## 5. 范式选择

- OOP：领域建模、有状态实体。
- AOP：横切关注点。
- FP：数据转换、无状态处理。

## 6. C# / .NET 编码规范

| 成员 | 规范 | 示例 |
|------|------|------|
| 命名空间/类/接口/方法/属性/常量 | PascalCase | `OrderService`、`IOrderRepo`、`GetById` |
| 私有字段 | _camelCase | `_orderRepo` |
| 局部变量/参数 | camelCase | `orderId` |

**关键约束**：不吞异常；不用 try-catch 做流程控制；异步方法 Async 结尾；避免 async void；不用 Task.Wait() 或 .Result。

## 7. SQL 数据库访问规范

- 参数化查询，严禁拼接 SQL；避免 `SELECT *`；大表查询必须含索引可用 WHERE。
- 外键必建索引；写操作包事务；事务尽量短（不含外部 API 调用）。
- 写入策略阈值以 `/rules/data-structure-analysis.md` §5.3 为唯一权威来源。
- 写操作必须幂等（唯一约束/幂等键/业务去重）。

## 8. 安全与日志

- 密钥/凭据/连接字符串：禁硬编码、禁提交版本库、禁写入日志。
- 敏感字段（身份证/手机号/银行卡）：掩码后记录（`138****1234`）。
- 日志切面记录参数前必须先脱敏；金额不得与个人标识同条出现。

## 9. 行为准则

- 编码前思考：假设→确认；歧义→列出选项；困惑→立即暂停。
- 简洁优先：不加要求外的功能；不为一次性代码建抽象。
- 精准修改：不改相邻代码/注释/格式；匹配现有风格。
- 目标驱动：每步可验证，分步确认。
