# 数据结构分析

## 实体识别
提取名词、修饰词、动词，过滤无标识无生命周期的候选。

## 关系建模
1:1 外键+唯一约束；1:N 外键放多侧；N:M 关联表。以业务语义为准，非当前代码实现。

## 字段推导
查询条件、结果显示、关联键字段，标注来源（原表/聚合计算/关联查询/外部 API）。

## 冗余权衡
- 查询频繁 + 字段 ≤3 + 更新频率低 → 允许冗余
- 一致性要求高或更新频率高 → 必须规范化

## 索引策略
从查询推导：WHERE 等值 → 范围 → JOIN（外键必建）→ ORDER BY → INCLUDE。低选择性字段不单独建索引。

## 性能、容量与写入策略

性能和容量结论必须由目标与测量驱动，不只由记录条数或经验阈值决定：

1. 明确成功指标：延迟、吞吐、峰值内存、数据库负载、锁等待、成本、失败率或维护窗口；没有目标时不得把“更快”当作已证实需求。
2. 记录工作负载：数据量与分布、并发度、事务边界、网络往返、索引与约束、是否需要返回生成值、幂等与失败恢复要求。
3. 建立可重复基线：固定环境、版本、输入和测量方法；优先基准、剖析、查询计划或生产遥测，不用单次主观观察下结论。
4. 选择最小充分策略：逐条、批量 API、数据库原生导入、流水线或分片都只是候选；以项目实测、数据库官方约束和兼容边界决定。
5. 验证最坏路径与正确性：检查事务时长、锁、日志/复制压力、内存、超时、部分失败、重试与回退；性能提升不得牺牲数据一致性和可恢复性。

没有项目数据时可用小规模试验或官方建议形成待验证假设，但不得把固定数量阈值写成通用门槛。非关系型存储按对应产品语义和实测决定。
