# 数据流推导

## 六步追踪法
1. 确定来源或创建点 2. 识别输入表示 3. 追踪传递与关系 4. 记录字段和约束变换 5. 标记存储与输出表示 6. 绘制链路

## 固定推导顺序
来源/创建 → 校验 → 查询/补全 → 变换 → 调用/解析 → 写入/传递 → 输出（按实际存在环节，不强行填充）。

类型、Schema、表或对象名称只是数据表示的标签。跨表示追踪时按 `./data-structure-analysis.md` 建立数据实体和证据化关系，不依据名称引入现实领域知识。

## 节点标注
节点名称（动词短语）、类型（创建/校验/内存变换/持久化读取/持久化写入/查询/外部 API/文件 IO/缓存）、执行构件、输入输出表示、字段或约束变化、依赖节点、关联数据实体、证据位置；只有存在有效业务依据时才关联业务步骤。内存变换描述进程内表示和计算；持久化处理描述存储边界、事务、可见性、恢复和迁移，不因节点类型不同就预设代码分层。

## 状态边界

按实际存在的状态分别记录：业务状态（业务生命周期与规则）、数据状态（表示、有效性与完整性）、执行状态（运行中、重试、取消、失败或完成）、持久化状态（未写入、已提交、可见或恢复中）、并发状态（版本、租约、锁或冲突）和外部副作用状态（未发送、已发送、已确认、补偿或未知）。只记录影响当前路径、正确性、恢复或观察的状态；没有证据时不合并或补造状态机。

## 存储
写入 `/documents/data-flow.md`，包含链路图（ASCII）、节点详情、表示映射和字段变换。现实语义未验证或与编码任务无关时使用中性数据名称，不补写行业含义。
