# 业务分析与决策

## 1. 业务流与数据流
分离记录，双向关联。业务流描述"做什么"，数据流描述"数据怎么变"。通过 `/documents/data-flow.md` 全局映射表关联。

## 2. 变更影响分析

| 场景 | 动作 |
|------|------|
| 新增/修改业务步骤 | 定位步骤 → 扫描关联数据流节点 → 评估 DB/API/测试影响 |
| 新增/修改数据流节点 | 定位节点 → 反向查业务步骤 → 确认用户可见影响 |
| 数据库表结构变更 | 找依赖节点 → 评估读写影响 → 确定迁移需求 |
| 外部 API 变更 | 契约对比 → 评估解析/降级 → 版本兼容 |

输出影响清单：受影响元素、类型、影响说明、优先级。

## 3. 决策框架

四步流程：识别冲突 → 比较所有真实可行路径及主要优缺点 → 推荐方案及理由 → 标注影响范围。通常至少比较两个候选；若证据表明只有一个可行路径，明确其他方向的排除依据，并把“维持现状 / 暂不实施”作为基线，不为满足数量要求编造伪方案。

决策记录在 `/documents/decision-log.md`，包含：编号、日期、标题、状态（active / rejected / superseded）、冲突点、背景、方案对比、最终选择、影响范围、重提条件（rejected 时必填：满足该条件前，相同提案不再重新评估）、跟进。

新建决策条件（三者同时满足）：难以撤销、无上下文会惊讶、存在真实权衡。任一不满足则不建档。

### 决策优先级

1. 数据安全/正确性 > 性能
2. 可维护性 > 代码简洁性
3. 显式 > 隐式
4. 内部一致性 > 外部最佳实践

## 4. 回查

当 `/rules/agent.md` 的多维任务画像、能力路由或强制门禁要求执行决策回查时：
1. 检索 `/documents/decision-log.md` 索引表，以任务关键词结合 `/documents/glossary.md` 同义术语扩展匹配；同一决策可能以不同术语被重提，命中任一同义术语即按命中处理。
2. 命中冲突 → 输出冲突提示（编号+摘要+冲突点+调和建议）并暂停。命中状态为 rejected 的决策时，输出该决策记录的重提条件；仅在条件满足时才重新评估。
3. 不冲突则标注关系（补充/增强/替代），继续。

### 独立缺陷快速路径

局部缺陷修复只有同时满足以下条件，才可免于检索 `decision-log`：

1. 目标行为有直接、可验证的依据，例如既有契约、已有测试、对照实现或用户明确确认；当前偏差可通过失败测试、稳定复现或等价证据证明。存在多个对照实现且彼此矛盾时，视为无直接依据。
2. 修改局限于既有实现接缝，不需要在多个真实设计方案之间选择。
3. 不改变公开 API、Schema、数据格式、业务规则、权限、架构边界、共享配置或全局执行顺序。
4. 影响范围可由代码引用、调用关系和测试闭环，且没有证据表明缺陷与历史设计选择有关。

使用快速路径时，简要记录目标行为依据、修改边界和排除项。任一条件不满足或无法确认时，执行标准回查。快速路径只免除历史决策检索，不免除影响分析、风险升级、测试和完成验证。

## 5. 破坏性影响分析（业务维度）

检查：规则冲突、目标冲突、流程冲突、语义冲突、权限冲突。

> 完整破坏性分析（分级、预测、标记、累积升级）以 `/rules/destructive-analysis.md` 为准。

## 6. 业务规则分析

涉及状态、金额、权限、角色或其他业务决策时：
1. 定位并引用 `/documents/business-rules.md` 中的对应规则条目；没有可验证依据时，不得推测目标行为。
2. 识别时间、状态、金额、角色等边界条件，选取最多 3 个与当前改动直接相关的关键场景请求确认。
3. 使用伪代码或流程图明确前置条件、全部判断分支和返回结果。
4. 实现时在关键判断处标注对应业务规则编号；规则缺失、冲突或边界不明确且影响正确性时暂停。
