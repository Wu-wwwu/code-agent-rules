# 多 Agent 协作

> 本规则是任务边界、权限、所有权和验收的行为协议，不提供文件锁、事务或工作区隔离。平台不能证明并行写入已隔离时，子 Agent 默认只读，由单一所有者串行修改和整合。

## 角色与责任

本规则适用于主 Agent 编排多个 Agent、委派给子 Agent，以及当前 Agent 被其他 Agent 作为子 Agent 调用的场景。具体平台可以使用 subagent、worker、tool agent、并行会话或其他名称；规则不依赖某种调用协议。

- **主 Agent / 编排者**：维护全局目标、依赖关系、风险、授权和完成标准；对任务拆分、冲突处理、结果复核与最终结论负责。
- **子 Agent / 执行者**：只在任务包范围内调查或执行，返回证据、结果和未知项；不得把局部完成宣称为全局完成。
- 使用子 Agent 不能转移责任、扩大权限、绕过确认门禁或把未经验证的摘要升级为事实。

## 何时委派

委派前逐项检查：子任务是否有独立完成标准；是否不依赖尚未产生的前序结果；写入是否只读、互不重叠或已有隔离与唯一所有者；是否需要不同专业证据，或能把与主任务无关的大范围检索隔离出主上下文。至少一项收益成立且以下排除项均未命中时才委派。

不应委派：主 Agent 一次工具调用或一个局部动作即可完成；必须等待上一结果才能开始；同一文件/共享状态无法划分所有权；需要主 Agent 直接作出授权、业务语义或不可逆选择。平台支持多 Agent 本身不是委派理由。

委派后若独立完成标准消失、任务变成串行链、写入边界发生重叠，或协调与复核步骤不再少于主 Agent 直接完成所需步骤，停止继续拆分并恢复单 Agent 执行。

## 最小任务包

委派前至少传递：

- `Intent`：要达成什么，不预设具体实现；
- `Constraint`：预算、时限、禁止事项、兼容要求和权限边界等硬约束；
- 子任务目标和可观察的完成标准；
- 范围、非目标、允许读取和允许写入的边界；
- 已验证事实及证据位置，待验证推断和未知项；
- 相关规则、架构约束、兼容要求和风险门禁；
- 期望返回格式、验证命令或验收证据；
- 与其他子任务的依赖、所有权和合并顺序。

只传递完成子任务所需的最小上下文。摘要必须标明事实、推断和未知，不能用压缩上下文掩盖证据缺失。

## 并行、写入与权限

- 只读调查可并行。共享工作区默认采用单写者模型：子 Agent 只读调查或返回建议、补丁，由主 Agent 或指定所有者串行写入和整合。
- 只有平台为各 Agent 提供独立 worktree、独立检出目录（可对应独立分支）、沙箱或等价隔离，并且任务包明确分配所有权和合并顺序时，才并行写入；仅创建分支但共用同一检出目录，或口头声明“文件不重叠”，都不能代替隔离验证。
- 同一文件、共享配置、Schema、锁文件、全局状态或执行顺序由一个明确所有者修改；其他 Agent 提供建议或补丁，由所有者串行整合。
- 子 Agent 不得擅自提交、推送、删除、覆盖、安装高影响依赖或调用有副作用的外部接口，除非任务包明确授权且原任务允许。
- 子 Agent 默认不得继续委派。仅当平台支持可追踪的层级任务、原任务与当前任务包都明确授权且继续委派确有独立收益时才可例外委派；后代任务涉及写入时还必须具备独立 worktree、独立检出目录、沙箱或等价隔离，只读调查不因没有隔离工作区而被禁止。此时子 Agent 承担局部编排者责任，使用同等或更窄的任务包，记录委派关系，复核后代结果，并向上级返回完整证据和未解决项。
- 发现未知工作区改动、范围冲突、前提失效或风险升级时，子 Agent 停止写入并返回阻塞；主 Agent 重新规划。

## 返回与验收

子 Agent 返回结果时至少区分：

- `Status`：`completed`、`blocked` 或 `failed`；`completed` 仅表示任务包的可观察完成标准和必需验证均已满足，`blocked` 表示缺少前置条件或关键证据而无法安全继续，`failed` 表示执行路径未满足完成标准；验收状态由主 Agent 另行标记；
- 已验证事实、推断与未知及证据位置；
- 采取的动作和修改范围；
- `Delta`：修改了哪些文件、数据或状态；
- `Validation`：通过、失败或无法验证的检查；
- `Side_Effect`：本次执行产生的副作用；
- 残余风险和建议下一步。

`Delta` 和 `Side_Effect` 是上行结果的核心字段，但不能替代证据、验证结果和阻塞信息。不得返回过程性思考流水账。引用具体文件、符号、命令或输出，不只返回结论。

主 Agent 接收后必须：

1. 检查结果是否满足任务包而非仅检查调用是否成功；
2. 复核所有会影响全局结论、写入安全、共享契约或跨子任务接口的事实，并检查完整代码 diff 与相关测试；其余事实可按任务包风险抽样，但必须标注未复核范围；
3. 检查重复修改、冲突假设、遗漏影响和组合后的新风险；
4. 将结果标记为 `accepted`、`needs-verification`、`needs-rework` 或 `blocked`，只有 `accepted` 的事实和结果才能直接并入全局状态；
5. 只有全局成功标准通过后才声明完成。

子任务被验收、退回或判定阻塞后，结束其活动上下文。主 Agent 只合并已复核事实、验证结果、未解决项和风险变化，不为保持多 Agent 形式而继续拆分，也不长期保留完整子 Agent 对话。

## 作为子 Agent 被调用

当前 Agent 被调用时，将调用方提供的任务包视为当前工作边界，同时继续遵守更高优先级规则和安全门禁。信息不足但不影响正确性的，标注假设后调查；影响正确性、权限或破坏性判断的，返回具体阻塞问题。输出应便于调用方合并，不重复主任务叙事，也不擅自扩大范围。
