# 模块目标生命周期

## 适用范围

当任务跨阶段构建模块功能、拆分可独立验收的子目标、暂停/恢复/切换目标，或要求对照基线方案与当前成果时加载本方法。单步局部修改、目标和验证接缝明确且不涉及目标切换时沿用 `agent.md` 轻量路径。

本方法管理当前目标、依赖、验证和交接状态；不替代风险分级与授权确认、领域规则、决策依据生命周期或项目文档规则，也不要求保存逐轮工作日志。

## 目标工作单元

每个可独立验收的目标作为一个工作单元。复杂功能只有在子目标有独立验收条件且依赖可说明时才拆分。恢复、切换、暂停或交接时，维护足以继续工作的最小状态：

| 字段 | 必要内容 |
|------|----------|
| 目标 | 当前可观察结果及验收条件 |
| 状态 | `proposed`、`active`、`paused`、`blocked`、`completed` 或 `superseded` |
| 边界 | 范围、非目标和授权限制 |
| 当前基线 | 相关实现事实、约束及直接证据位置 |
| 临时方案 | 只记录影响后续动作的当前实现选择及依据；无影响则省略 |
| 验证与差异 | 已执行验证、实际结果、目标差异和未完成风险 |
| 下一动作 | 一个获授权、可验证的动作；无动作时写明阻塞或终止状态 |

不要求每轮输出完整状态表；只更新变化字段。状态表用于恢复与控制目标流转，不作为项目事实或独立决策档案。

## 模块局部工作区

跨阶段、可暂停/切换/交接，或需要反复建模与验证的模块，优先在一个模块目录内组织相关工作材料。沿用项目已有目录和文档；没有合适位置时，只有项目文档规则允许时才创建。不得把本结构强制用于单步局部任务。

```text
<module-workspace>/
  README.md                 # 局部入口、当前目标/状态、权威资料导航、材料用途与清理条件
  work-items/<goal-id>.md   # 目标、边界、状态、临时方案、依赖、下一步
  decisions.md              # 本模块仍影响当前或后续工作的决策依据；需要时创建
  models/                    # 本模块目标需要且仍有用的局部模型；需要时创建
  validation/                # 基线、模拟、回归和核对材料；需要时创建
```

README 是导航和状态入口，不复制实现细节、完整决策正文、模型或测试结果。项目级业务规则、接口契约和当前实现事实仍由项目权威文档维护；局部材料记录本模块工作所需的上下文并引用权威来源。模块现有主计划已能承担状态入口时，直接沿用，不再创建第二个 README 或主计划。

### 局部决策保留

- 模块未完成，或尚未明确执行清理前，保留仍可能影响本模块目标、方案、实现、验证、依赖或后续切换的决策，包括临时决策及其当前状态和依据。保留不等于逐轮记日志：只写决策内容、适用范围、证据/依据、状态（临时、采用、否决、被替代或待验证）及会改变后续动作的条件。
- 同一决策只维护一个权威条目。不同文档引用该条目；重复内容合并后保留最新有效表述及仍需追溯的依据，不因合并丢失尚未解决的依赖、否决条件或兼容/恢复约束。
- 无当前影响的讨论、重复理由、用户原话、确认过程、主观评价和未验证后果不属于决策条目。已失效但可能解释当前依赖或清理判断的条目标为被替代/失效并给出证据，不得继续作为当前约束。
- 模块目标完成本身不自动授权删除决策。只有用户/项目授权或既定清理规则允许，且核对无当前依赖、审计/留存义务、兼容/迁移/恢复用途后，才清理局部材料；清理前更新权威文档引用并记录必要的当前结论。否则保留并退出默认查询。

### 局部模型与验证材料

只在能改变实现、风险判断或验收结论时，维护模块范围内的职责/数据模型、流程或状态模型、模拟输入与结果、基线和回归核对。每项材料应标明对应目标、适用范围、证据来源和验证状态；区分模拟与真实输入、单元测试与生产验收。避免把同一规则复制到模型、决策和项目文档；保留一个权威位置，其余交叉引用。

基线用于本目标内比较，不等于永久不变的实现事实。实现、配置、Schema、输入样本或验收条件变化时，重核受影响的基线与验证结论，并更新、标记过期或按清理规则移除；不删除仍支撑未完成目标的材料。

## 状态流转

- `proposed -> active`：目标、范围、验收条件和授权足以开始。
- `active -> paused`：暂缓但保留继续条件、依赖和下一动作；恢复时复核相关证据的新鲜度。
- `active -> blocked`：缺少必要证据、授权、环境或外部条件，列明阻塞依据和解除条件；不把可独立推进的授权工作一并冻结。
- `active -> completed`：目标验收条件有匹配的实际验证证据；部分实现或未验证不得标为完成。
- `proposed|active|paused -> superseded`：新目标取代旧目标；说明取代关系及仍被新目标依赖的有效约束、产物或未解决风险。`superseded` 不表示已完成。

目标、范围、验收条件、关键约束或授权变化时，重新校准受影响状态；不因目标变化自动丢弃仍适用的证据，也不把旧目标假设自动沿用到新目标。

## 执行与临时选择

1. 确认当前目标、成功标准、非目标、授权和与基线目标的关系。
2. 读取单一权威状态说明及本目标所需的实现、规则和验证证据；按适用范围复核新鲜度和冲突，不恢复全部历史过程。
3. 形成足以决定下一动作的最小模型：职责/调用路径、关键不变量、数据及状态变化、副作用边界和验证接缝；局部直接任务不强制建模。
4. 临时实现选择记录在本模块唯一决策条目或工作单元中，说明选择本身、适用范围、状态和足以支持它的证据。模块未完成或未明确清理前，仍影响后续动作的选择不得因“临时”而丢失；只有满足 `business-analysis.md`「新建决策条件」且超出本模块局部范围时，才升级为项目级独立决策依据。
5. 每个动作后核对预期与实际，更新受影响状态并选择继续、暂停、阻塞、撤销或完成；按任务真实风险触发受控变更和授权确认。

临时选择不是自动成为项目级长期规则。模块局部保留要求不代表必须把每个选择独立建档：优先维护在本模块唯一决策条目中，代码、配置和测试能直接表达且不影响本模块未完成目标的选择可不记录；产生模块外仍有效的业务、兼容、安全、迁移或恢复约束时，按项目文档与决策依据规则就地维护。

## 目标对照与收尾

完成、切换或交接时，对照当前有效的基线目标和成功标准，使用状态性断言而非叙事性过程：

- 已验证满足：`<能力/属性> 当前 <值/状态> 满足目标 <条件>，证据 <位置>`
- 未满足/调整：`<能力> 当前 <值/状态>，目标 <条件>，差异 <Δ>，原因 <依据>`
- 未完成风险：`<风险> 当前 <状态>，触发条件 <C>，缓解 <措施>`
- 本次实际改变的权威文档位置，或无需写回的理由

禁止输出"完成了功能 X""修复了问题 Y""团队决定 Z"作为状态说明；这些是过程叙事，不是状态断言。只更新已验证且仍适用的当前状态、规则、流程、模型、验证结果和剩余工作。基线方案是比较依据，不是高于当前有效授权、业务规则、契约或代码证据的永久事实。按 `document-init.md` 写回、去重和失效规则处理；不得为了保留过程而恢复逐轮决策史。

纯局部任务或没有跨目标恢复/交接需求时，本方法退出，不要求创建模块目录、局部 README、完整计划或额外报告格式。
