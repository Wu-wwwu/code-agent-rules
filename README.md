# Code Agent Rules

> 让 AI Coding Agent 依据项目证据形成认知、执行改动并验证结果。

## 这是什么

一个可以被 AI Coding Agent 加载的**规则集**。它不是仅供人类阅读的编码规范文档，而是直接嵌入 Agent 工作流的**行为约束与认知规范**：

- 什么能改、什么不能改
- 改动前先获取什么证据、做什么评估
- 遇到 Bug 按什么流程诊断
- 什么时候该抽象、什么时候不该抽象
- 业务逻辑怎么分析、数据流怎么追踪

仓库提供四份可独立采用的版本，**默认使用 `mini/`**：`mini/` 是压缩后的触发式默认版，`lite/` 是带自包含专项方法和按需项目记忆模板的轻量版，`rules/` 是配套固定项目文档体系的强约束版，`self/` 是从现有项目证据动态形成认知的自适应版。四份版本互不依赖，使用方可按场景单独复制、加载和维护。

│  ├─ coding-principles.md # 中立的编码行为、设计判断与验证边界

├─ documents/    # Mini / 强约束版可选的项目文档模板

## 怎么用

在 AI Coding Agent 的系统提示或项目配置中选择一份版本引用。以 Cline 为例，可将所选版本配置为自动加载；其他 Agent 平台对应机制类似：

- **Mini 默认版**：默认只常驻 `mini/agent.md`，任务开始或范围变化时读取短路由表 `mini/triggers.md`，命中候选信号后才加载对应 `methods/` 确认详细适用条件。保留安全、证据、闭环和关键专项能力，同时降低任务级加载成本；`documents/` 是按需检查和初始化的可选项目记忆库，缺失本身不阻塞普通任务。
- **Lite 版**：常驻 `lite/agent.md`，按 `lite/triggers.md` 加载最少的自包含方法。项目长期记忆通过 `lite/methods/project-documents.md` 与 `templates.md` 按需创建；安装时不预置根 `documents/`。
- **强约束版**：使用 `rules/agent.md` 及其专项规则，按需创建或显式安装 `documents/`。含固定项目文档体系与决策回查（组织记忆）。适合团队需要统一项目记忆、明确门禁和可审计流程的场景。
- **Self 独立版**：默认只加载 `self/core.md`；触发复杂场景时再依据 `self/README.md` 加载本目录对应模块。适合资料形态不固定，希望 Agent 从代码、配置、测试、运行结果、历史和用户说明中动态形成项目认知，并自主确定语言、技术栈和实现方向的场景。Self 版支持就地维护选择依据和必要的定向追溯，但不提供固定的独立决策档案体系；需要统一档案格式时采用强约束版或项目自有规范。

### 强约束版最小起步

先加载 `rules/agent.md` 及当前任务实际触发的专项规则；`documents/` 不要求一次建齐。先复用当前上下文中仍适用的直接证据，只有缺失、过期、冲突或范围变化时再读取或创建文档。首次任务只补当前动作依赖的记录；文档缺失本身不阻塞任务，只有缺失信息会影响正确性时才暂停。具体创建条件和最小内容见 `rules/document-init.md`。

### 版本组合边界

四份版本不是连接关系、替代层或兼容层，也不要求互相引用。选择其中一份即可独立运行；组合不是仓库的默认用法，也不在现有回归基准覆盖范围内。若使用方确需组合，只选择一个版本作为总控入口，其他版本仅作为按需方法补充；出现重叠或冲突时以总控版本为准，不将多个入口同时设为并列最高规则。

Self 独立版不会给模型增加其原本没有的推理或工具能力。对成熟 Agent，它主要用于降低长任务目标漂移、证据与目标混淆、假阳性验证和高风险误操作；简单任务上的增益通常很小。若平台系统提示已经提供等价约束，应在接入时选择或合并，避免增加上下文和流程负担。

四个版本都不替代具体平台的工具调度，也不要求平台必须支持多 Agent。协作规则是任务边界和验收协议，不提供文件锁、事务或工作区隔离；平台不能证明独立工作区时，子 Agent 默认只读并由单一所有者串行整合。平台支持委派时，同一规则既可作为主 Agent 的编排约束，也可作为子 Agent 的执行契约；平台不支持时由单 Agent 按相同循环执行。它们各自在自己的规则边界内约束 Agent 的观察、执行和反馈循环：

```
任务开始/恢复
   ↓
校准目标、成功标准、状态和风险
   ↓
加载下一动作所需的最小知识
   ↓
选择并执行一个可验证动作
   ↓
校验实际结果并更新上下文
   ↓
继续 / 暂停 / 阻塞 / 回退 / 完成
```

四个版本都采用漏斗式深度：默认走满足目标的最轻路径，发现业务、安全、契约、数据、技术方向、验证或回退信号时才加载对应能力或升级门禁；触发义务完成后退出能力并恢复轻量路径。Mini 版以规范和方法路由压缩常驻上下文，Lite 版进一步提供自包含方法与内置项目记忆模板，强约束版额外提供完整固定项目文档体系（文档模板按需或显式安装），Self 版保持最小核心并按触发加载模块。

## 跨工具使用

规则正文与具体工具无关（见「设计原则 · 跨 Agent 可移植」）。根目录 `AGENTS.md` 和 `CLAUDE.md` 都是**纯指针文件**，不是规则正文、安装说明或版本选择菜单；安装完成后必须且只能包含一个规则入口路径。其他工具可在其实际支持的项目指令位置使用同一个纯指针，不假定仓库中存在未提供的专属文件。

### `AGENTS.md` 单指针契约

- 文件只能有一行非空内容，内容是裸路径；不得附加标题、列表符号、注释、代码围栏或第二个候选入口。
- 指针只能选择一个总控版本：Mini 默认版指向 `mini/agent.md`，Lite 版指向 `lite/agent.md`，强约束版指向 `rules/agent.md`，Self 独立版指向 `self/core.md`。
- 规则随目标项目保存时使用相对路径；规则集中安装时使用该入口文件的固定绝对路径。两种方式都不得同时写入。
- 用户手动安装或由 LLM / 安装器安装时，应**覆盖**目标项目原有的规则指针，而不是把新入口追加到文件中；覆盖前仍须遵守用户授权并处理已有自定义内容。
- 安装结束必须回读文件，确认最终状态只有一个指针，并确认所选路径可访问。

### 平台加载验收

裸路径只是本仓库的指针契约，不自动证明目标平台会把它当作 include 指令。接入每个 Agent 平台时必须用最小测试项目验证：入口是否实际加载、相对路径基准、用户级绝对路径、方法文件按需加载和 `AGENTS.md`/`CLAUDE.md` 同时存在时的优先级。若平台不支持裸路径，应使用该平台的引用语法或安装完整规则内容，而不是把路径当作普通提示交付。

同一项目同时存在 `AGENTS.md` 与 `CLAUDE.md` 时，两者必须指向同一个总控版本；不能依赖平台未声明的优先级让两个版本并行生效。

项目内安装四选一：

```text
mini/agent.md
```

```text
lite/agent.md
```

```text

```

```text
self/core.md
```

固定路径安装示例（实际路径以安装位置为准）：

```text

```

### 安装辅助

仓库根目录的 `install.py` 使用 Python 标准库运行，支持把规则复制到某个项目，或为某个 Code Agent 写入用户级规则指针。所有模式默认先做冲突检查：目标已有不同内容时不写入；确认覆盖时使用 `--force`，安装器会先创建带时间戳的 `.bak` 备份。可先加 `--dry-run` 只查看计划。

安装到项目（默认 Mini 版）：

```bash
py install.py project D:/work/my-project --dry-run
py install.py project D:/work/my-project
py install.py project D:/work/my-project --edition lite
py install.py project D:/work/my-project --edition self
py install.py project D:/work/my-project --edition rules
```

需要显式复制项目文档模板时：

```bash
py install.py project D:/work/my-project --edition rules --include-documents
```

`documents/` 中的内容是模板或待验证材料，不能直接作为项目事实；默认不安装它们可避免示例数据污染目标项目。

兼容性说明：当前版本将 Mini/Rules 的项目文档模板由默认复制改为显式 `--include-documents`。依赖旧默认行为的安装脚本必须加入该参数；规则文件的默认安装和入口路径不变。

- Mini 版默认只复制 `mini/`；需要项目文档模板时显式加入 `--include-documents`，并写入 `AGENTS.md -> mini/agent.md`；项目文档是可选记忆，规则运行不以其预先存在为前提。
- Lite 版只复制 `lite/` 并写入 `AGENTS.md -> lite/agent.md`；需要长期项目记忆时由 Lite 方法按需创建 `documents/`。
- Self 版复制 `self/` 并写入 `AGENTS.md -> self/core.md`；使用 `--edition self` 显式选择。
- 强约束版默认只复制 `rules/`；需要项目文档模板时显式加入 `--include-documents`，并写入 `AGENTS.md -> rules/agent.md`；已有项目文档始终保留，不会被模板覆盖。
- 目标工具使用其他项目入口文件时，可通过 `--entry-file CLAUDE.md` 或相应相对路径指定。
- 目录复制自动排除 `__pycache__`、`.pytest_cache`、`.git` 和 `*.pyc` 等生成缓存；写入中途失败时恢复本轮已覆盖的原文件并清理本轮新建文件。

安装到 Code Agent 用户级入口（写入指向本仓库规则入口的绝对路径）：

```bash
py install.py agent cline --dry-run
py install.py agent cline
py install.py agent cline --edition self
py install.py agent claude --edition rules
py install.py agent codex --edition self
py install.py agent custom --entry-file D:/agent-config/RULES.md --edition self
```

内置预设分别使用当前用户目录下的 Cline `Documents/Cline/Rules/AGENTS.md`、Claude Code `.claude/CLAUDE.md` 和 Codex `.codex/AGENTS.md`。不同版本或安装方式若采用其他位置，使用 `--entry-file` 显式覆盖；安装后本仓库路径不能随意移动，否则绝对指针会失效。运行 `py install.py --help` 查看完整参数。

### 选择版本

在所用工具的入口文件中写入所选版本的**唯一指针**（四版独立，不要同时启用）：

- **Mini 默认版**：读取并遵循 `mini/agent.md`；任务开始或范围变化时用 `mini/triggers.md` 识别候选信号，命中后加载最少的 `mini/methods/` 文件确认详细适用条件。
- **Lite 版**：读取并遵循 `lite/agent.md`；用 `lite/triggers.md` 按需加载自包含的 `lite/methods/`。
- **强约束版**：读取并遵循 `rules/agent.md`，按其中“能力路由与知识加载”章节按需加载专项规则与 `documents/`。
- **Self 独立版**：读取并遵循 `self/core.md`，复杂场景按 `self/README.md` 触发表加载 `context` / `diagnosis` / `change` / `security` / `technology` / `collaboration` 模块。
- 四版均不预设编程语言、框架或数据库；相关选择按各自的技术选型规则从项目证据与用户边界中得出。四版均可被主 Agent 加载，也可作为子 Agent 的任务执行规则。
- 四版均不预设特定编程范式、分层模型或设计模式；Agent 依据现有代码、问题性质和验证成本决定实现方式，规则只限制复杂度、风险和可验证性。


## 设计原则

**漏斗式深度**。默认采用满足目标所需的最轻路径，不为简单任务先做完整分类；发现影响边界、业务或安全语义、技术方向、验证负担、不可逆性等否决信号时，再按实际触发扩展能力或升级门禁。触发义务完成后收缩回轻量路径。

**决策点内联约束**。某条规则实际控制即将执行的动作时，在对应的操作计划、工具调用说明或修改点旁，用完整自然语言重述当前最关键的约束，让约束与受控动作相邻。只重述本步命中的约束，不预先注入风险词清单，也不机械复制全部规则；完整触发条件和执行要求仍保留在常驻入口（强约束版）、候选路由短表与专项方法（Mini/Lite 版）或可路由模块（Self 版）中。

**循环校验**。工具调用成功不等于任务步骤成功；每个逻辑动作后都要比较预期和实际，并据此更新下一轮状态。

**状态门禁是行为协议，不是工具 hook**。四份入口各自包含同名小节「状态与继续门禁」（例如 `rules/agent.md`「状态与继续门禁」），约定 `写入前`、`继续前` 和 `完成前` 的判定，并按可观察逻辑动作而不是内部推理步数计算有效进展：事实证据、缩小关键未知或排除原因、确认阻塞、已授权交付物、验证义务或缺口、以及证据驱动的风险/范围/门禁变化才算进展。该协议只约束按规则运行的 Agent：不拦截未加载规则的会话，不承诺按 token 阈值、耗时或步数自动检测循环，也没有规则外的强制执行或监控背书。按需方法或模块“退出”只表示停止应用其附加流程，不等于从上下文删除已获得的结论和证据。恢复用状态文件是可选手段而非事实来源：其中的“已读/已完成”记录不自动获得已验证事实的可信度，复用前仍按来源、新鲜度和范围复核。

**终态双门禁**。代码收束要求最终产物只保留当前目标和已授权的兼容、迁移、验证、生成或回退所需内容，不遗留本任务引入的临时、重复、失效、不可达或无消费者路径；逻辑闭合要求每项成功标准都有可达实现、完整的受影响分支处理和匹配验证证据。达到目标后不借机清理范围外旧债，也不以 TODO、未接线实现或命令成功代替完成。

**证据复用与按需取证**。Agent 先复用仍然新鲜、直接且适用于当前范围的证据；只在缺失、过期、冲突或范围变化时补充下一动作所需的规则、项目事实和运行证据，不以工具调用数量证明充分性。

**版本独立**。`mini/`、`lite/`、`rules/` 与 `self/` 分别定义完整的接入边界。

**跨 Agent 可移植**。规则使用读取、搜索、修改、执行和验证等抽象行为，不绑定特定 Code Agent 的工具名称或内部实现。

**技术方向自主但不覆盖用户方向**。用户可只给目标与边界，由 Agent 依据文档、代码、配置、环境和验证结果识别或选择语言、技术栈与实现方向；用户明确指定技术时先核对兼容性，可行则遵循，冲突或会造成重大迁移时展示证据和选项。只有选择会改变高影响边界或依赖无法推导的非技术取舍时才升级确认。

**性能与工具链可证**。性能、容量或资源结论需要可重复基线和同负载比较；生成器、编译器、锁文件、迁移与部署产物都纳入影响分析。仓库、用户级和全局配置按实际作用域判断，只修改授权且生效的最小层级。

**可编排也可被编排**。支持单 Agent、主 Agent 调用多个子 Agent，以及当前 Agent 作为子 Agent 返回结构化证据；只有委派收益高于协调和复核成本时才扩展，任务收敛后恢复单 Agent。委派不转移最终验证责任。共享工作区默认采用单写者模型；子 Agent 默认不再委派，只有平台具备可追踪层级且任务明确授权时才例外允许，后代任务涉及写入时还必须具备独立工作区或等价隔离。

**设计方式中立**。不把任何编程范式、分层模型或设计模式当作默认答案。采用 Mini 版时按 `mini/methods/neutral-design.md`，采用 Lite 版时按 `lite/methods/neutral-design.md`，采用强约束版时按 `rules/coding-principles.md`，采用 Self 独立版时遵循 `self/core.md` 的最小充分原则；不要跨版本拼接最高规则。

**证据分层**。当前实现以代码、配置和运行结果为准；目标行为以用户确认的需求、业务规则和有效决策为准。两者冲突时显式标记，不擅自裁决；无法推导的内容标注“需用户提供”。

**选择依据随方案维护**。决策信息是当前技术方案、数据结构和流程调整的辅助证据，不是逐次追加的日志。同一依据只维护一个主要位置；先查当前说明，只有关键缺口、冲突、有效约束变化或用户要求时定向追溯历史。独立档案仅保存有未来复用价值、跨模块或跨文档需统一引用且符合建档条件的重要取舍。历史状态不自动成为当前约束，否决前提变化可重新评估。相关变更完成后，已失效且无当前依赖的依据退出默认查询；兼容、迁移、回退和审计留存单独核对，授权清理不改写版本历史，也不假定未提交内容已保存。

## 适用场景

适合嵌入任何使用 AI Coding Agent 的团队项目，作为 Agent 行为的统一标准。

## 规则回归验证

`eval/` 存放规则维护用的行为回归基准：前 4 个案例取材真实开源项目 issue（并发竞态诊断、金额门禁、依赖 major 升级、决策回查），另有技术选型、多 Agent、设计方式中立、动态执行深度、性能证据、工具链作用域、项目上下文、代码收束与逻辑闭合以及状态门禁与操作性判定等综合场景。每次修改规则后，将基准任务交给加载了被测规则的 Agent 并核对检查点，防止规则变更引入行为退化。用法与判定标准见 `eval/README.md`。

跨文件规则引用使用“文件路径 + 章节标题”而不是数字章节号。维护规则标题或引用后，运行 `py eval/check_rule_references.py`（也可用环境中的 `python`）检查目标文件、标题及遗留数字引用。
