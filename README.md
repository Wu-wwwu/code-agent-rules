# Code Agent Rules

> 让 AI Coding Agent 依据项目证据形成认知、执行改动并验证结果。

## 这是什么

一个可以被 AI Coding Agent 加载的**规则集**。它不是仅供人类阅读的编码规范文档，而是直接嵌入 Agent 工作流的**行为约束与认知锚点**：

- 什么能改、什么不能改
- 改动前先获取什么证据、做什么评估
- 遇到 Bug 按什么流程诊断
- 什么时候该抽象、什么时候不该抽象
- 业务逻辑怎么分析、数据流怎么追踪

仓库提供三份可独立采用的版本，**默认使用 `mini/`**：`mini/` 是压缩后的触发式版本，`rules/` 是配套固定项目文档体系的强约束版，`self/` 是从现有项目证据动态形成认知的自适应版。三份版本互不依赖，使用方可按场景单独复制、加载和维护。

## 目录结构

```text
.
├─ mini/         # Mini 默认版：基础锚点、触发表和按需专项方法
│  ├─ anchors.md # Mini 版默认入口
│  ├─ triggers.md # 专项方法触发表
│  └─ methods/   # 按需加载的分析与执行方法
├─ rules/        # 强约束版：行为总纲、分析方法和编码约束
│  ├─ agent.md   # 强约束版入口：固定文档体系、能力路由和执行门禁
│  ├─ coding-principles.md # 中立的编码行为、设计判断与验证边界
│  ├─ technology-selection.md # 从项目证据识别技术栈并在边界内自主选型
│  └─ agent-collaboration.md # 多 Agent 编排与子 Agent 契约
├─ documents/    # 强约束版配套的项目事实与决策记录示例
├─ self/         # Self 独立版：最小核心与按需能力模块
│  ├─ core.md    # Self 版精简默认入口
│  ├─ README.md  # Self 版说明及模块索引
│  ├─ context.md # 模块：上下文与项目认知
│  ├─ diagnosis.md # 模块：疑难 Bug 诊断
│  ├─ change.md  # 模块：兼容与迁移
│  ├─ security.md # 模块：安全控制
│  ├─ technology.md # 模块：技术识别与自主选型
│  └─ collaboration.md # 模块：多 Agent 协作
├─ eval/         # 规则回归验证基准（维护者使用）
├─ install.py    # 项目级 / Code Agent 用户级安装辅助
├─ AGENTS.md     # 跨工具纯指针入口：最终状态只保留一行规则路径
├─ CLAUDE.md     # Claude Code 专属入口
└─ README.md     # 本规则仓库说明
```

## 规则清单

| 文件 | 定位 | 核心内容 |
|------|------|----------|
| `mini/anchors.md` | Mini 版默认入口 | 常驻安全锚点、执行闭环与按需方法路由 |
| `mini/triggers.md` | Mini 版触发表 | 将业务、诊断、迁移、性能、多 Agent 等信号映射到专项方法 |
| `rules/agent.md` | 循环控制总纲 | 任务状态恢复、漏斗式执行深度、能力路由与退出、门禁和循环控制 |
| `self/core.md` | Self 版最小入口 | 目标、证据、最小动作、反馈、安全停机和完成门禁 |
| `self/README.md` | Self 版说明与能力索引 | 独立使用方式及按触发场景加载上下文、Bug、迁移或安全模块 |
| `rules/business-analysis.md` | 业务决策 | 变更影响分析、决策四步框架、冲突回查、优先级体系 |
| `rules/data-flow-methodology.md` | 数据追踪 | 六步追踪法、固定推导顺序、节点标注规范 |
| `rules/data-structure-analysis.md` | 数据建模与容量 | 实体识别、关系建模、字段推导、索引、性能基线和写入策略 |
| `rules/destructive-analysis.md` | 风险控制 | 变更分级、事前预测、工具链与配置作用域、扩展-收缩迁移模式 |
| `rules/diagnosing-bugs.md` | 排错流程 | 反馈回路→复现最小化→可证伪假设→插桩→修复→清理 |
| `rules/document-init.md` | 文档体系 | 8 类项目文档的创建时机、内容基准、初始化原则 |
| `rules/coding-principles.md` | 编码与设计准则 | 简洁与精准修改、证据驱动的实现选择、抽象判断、验证及安全边界 |
| `rules/technology-selection.md` | 技术自主决策 | 从需求、文档、代码和环境识别语言/技术栈，处理用户指定方向并在工程边界内选型 |
| `rules/agent-collaboration.md` | 多 Agent 协作 | 主/子 Agent 责任、任务包、单写者与隔离边界、结果复核与验收 |
| `self/technology.md` | Self 技术选型模块 | 不预设语言或框架，按证据与影响自主识别、选择和验证 |
| `self/collaboration.md` | Self 多 Agent 模块 | 编排、委派、子 Agent 返回和全局验收边界 |

`documents/` 下提供 8 类项目文档的最小示例。示例用于展示结构和写法，接入实际项目后必须依据代码与真实业务资料替换。

## 怎么用

在 AI Coding Agent 的系统提示或项目配置中选择一份版本引用。以 Cline 为例，可将所选版本配置为自动加载；其他 Agent 平台对应机制类似：

- **Mini 默认版**：默认只加载 `mini/anchors.md`，命中触发信号时通过 `mini/triggers.md` 加载对应 `methods/`。保留安全、证据、闭环和关键专项能力，同时降低常驻上下文成本；决策回查与业务规则方法依赖 `documents/`。
- **强约束版**：使用 `rules/agent.md` 及其专项规则，并配套 `documents/`。含固定项目文档体系与决策回查（组织记忆）。适合团队需要统一项目记忆、明确门禁和可审计流程的场景。
- **Self 独立版**：默认只加载 `self/core.md`；触发复杂场景时再依据 `self/README.md` 加载本目录对应模块。适合资料形态不固定，希望 Agent 从代码、配置、测试、运行结果、历史和用户说明中动态形成项目认知，并自主确定语言、技术栈和实现方向的场景。Self 版不提供决策档案与回查等组织记忆能力；长周期项目如需该能力，应采用强约束版或自行补充决策记录。

### 强约束版最小起步

先加载 `rules/agent.md` 及当前任务实际触发的专项规则；`documents/` 不要求一次建齐。先复用当前上下文中仍适用的直接证据，只有缺失、过期、冲突或范围变化时再读取或创建文档。首次任务只补当前动作依赖的记录；文档缺失本身不阻塞任务，只有缺失信息会影响正确性时才暂停。具体创建条件和最小内容见 `rules/document-init.md`。

### 版本组合边界

三份版本不是连接关系、替代层或兼容层，也不要求互相引用。选择其中一份即可独立运行；组合不是仓库的默认用法，也不在现有回归基准覆盖范围内。若使用方确需组合，只选择一个版本作为总控入口，其他版本仅作为按需方法补充；出现重叠或冲突时以总控版本为准，不将多个入口同时设为并列最高规则。

Self 独立版不会给模型增加其原本没有的推理或工具能力。对成熟 Agent，它主要用于降低长任务目标漂移、证据与目标混淆、假阳性验证和高风险误操作；简单任务上的增益通常很小。若平台系统提示已经提供等价约束，应在接入时选择或合并，避免增加上下文和流程负担。

三个版本都不替代具体平台的工具调度，也不要求平台必须支持多 Agent。协作规则是任务边界和验收协议，不提供文件锁、事务或工作区隔离；平台不能证明独立工作区时，子 Agent 默认只读并由单一所有者串行整合。平台支持委派时，同一规则既可作为主 Agent 的编排约束，也可作为子 Agent 的执行契约；平台不支持时由单 Agent 按相同循环执行。它们各自在自己的规则边界内约束 Agent 的观察、执行和反馈循环：

```
任务开始/恢复
   ↓
校准目标、成功标准、状态和风险
   ↓
加载下一动作所需的最小知识
   ↓
选择并执行一个可验证动作
   ↓
校验实际结果并更新上下文
   ↓
继续 / 暂停 / 阻塞 / 回退 / 完成
```

三个版本都采用漏斗式深度：默认走满足目标的最轻路径，发现业务、安全、契约、数据、技术方向、验证或回退信号时才加载对应能力或升级门禁；触发义务完成后退出能力并恢复轻量路径。Mini 版以锚点和方法路由压缩常驻上下文，强约束版额外提供完整固定项目文档体系，Self 版保持最小核心并按触发加载模块。

## 跨工具使用

规则正文与具体工具无关（见「设计原则 · 跨 Agent 可移植」）。根目录 `AGENTS.md` 和 `CLAUDE.md` 都是**纯指针文件**，不是规则正文、安装说明或版本选择菜单；安装完成后必须且只能包含一个规则入口路径。其他工具可在其实际支持的项目指令位置使用同一个纯指针，不假定仓库中存在未提供的专属文件。

### `AGENTS.md` 单指针契约

- 文件只能有一行非空内容，内容是裸路径；不得附加标题、列表符号、注释、代码围栏或第二个候选入口。
- 指针只能选择一个总控版本：Mini 默认版指向 `mini/anchors.md`，强约束版指向 `rules/agent.md`，Self 独立版指向 `self/core.md`。
- 规则随目标项目保存时使用相对路径；规则集中安装时使用该入口文件的固定绝对路径。两种方式都不得同时写入。
- 用户手动安装或由 LLM / 安装器安装时，应**覆盖**目标项目原有的规则指针，而不是把新入口追加到文件中；覆盖前仍须遵守用户授权并处理已有自定义内容。
- 安装结束必须回读文件，确认最终状态只有一个指针，并确认所选路径可访问。

项目内安装三选一：

```text
mini/anchors.md
```

```text
rules/agent.md
```

```text
self/core.md
```

固定路径安装示例（实际路径以安装位置为准）：

```text
E:/agent-rules/rules-v3.02-hybrid-kimi/rules/agent.md
```

### 安装辅助

仓库根目录的 `install.py` 使用 Python 标准库运行，支持把规则复制到某个项目，或为某个 Code Agent 写入用户级规则指针。所有模式默认先做冲突检查：目标已有不同内容时不写入；确认覆盖时使用 `--force`，安装器会先创建带时间戳的 `.bak` 备份。可先加 `--dry-run` 只查看计划。

安装到项目（默认 Mini 版）：

```bash
py install.py project D:/work/my-project --dry-run
py install.py project D:/work/my-project
py install.py project D:/work/my-project --edition self
py install.py project D:/work/my-project --edition rules
```

- Mini 版复制 `mini/`，补充项目中尚不存在的 `documents/` 模板，并写入 `AGENTS.md -> mini/anchors.md`。
- Self 版复制 `self/` 并写入 `AGENTS.md -> self/core.md`；使用 `--edition self` 显式选择。
- 强约束版复制 `rules/`，补充项目中尚不存在的 `documents/` 模板，并写入 `AGENTS.md -> rules/agent.md`；已有项目文档始终保留，不会被模板覆盖。
- 目标工具使用其他项目入口文件时，可通过 `--entry-file CLAUDE.md` 或相应相对路径指定。

安装到 Code Agent 用户级入口（写入指向本仓库规则入口的绝对路径）：

```bash
py install.py agent cline --dry-run
py install.py agent cline
py install.py agent cline --edition self
py install.py agent claude --edition rules
py install.py agent codex --edition self
py install.py agent custom --entry-file D:/agent-config/RULES.md --edition self
```

内置预设分别使用当前用户目录下的 Cline `Documents/Cline/Rules/AGENTS.md`、Claude Code `.claude/CLAUDE.md` 和 Codex `.codex/AGENTS.md`。不同版本或安装方式若采用其他位置，使用 `--entry-file` 显式覆盖；安装后本仓库路径不能随意移动，否则绝对指针会失效。运行 `py install.py --help` 查看完整参数。

### 选择版本

在所用工具的入口文件中写入所选版本的**唯一指针**（三版独立，不要同时启用）：

- **Mini 默认版**：读取并遵循 `mini/anchors.md`，命中其触发条件时读取 `mini/triggers.md` 并加载对应 `mini/methods/` 文件。
- **强约束版**：读取并遵循 `rules/agent.md`，按其中“能力路由与知识加载”章节按需加载专项规则与 `documents/`。
- **Self 独立版**：读取并遵循 `self/core.md`，复杂场景按 `self/README.md` 触发表加载 `context` / `diagnosis` / `change` / `security` / `technology` / `collaboration` 模块。
- 三版均不预设编程语言、框架或数据库；相关选择按各自的技术选型规则从项目证据与用户边界中得出。三版均可被主 Agent 加载，也可作为子 Agent 的任务执行规则。
- 三版均不预设特定编程范式、分层模型或设计模式；Agent 依据现有代码、问题性质和验证成本决定实现方式，规则只限制复杂度、风险和可验证性。


## 设计原则

**漏斗式深度**。默认采用满足目标所需的最轻路径，不为简单任务先做完整分类；发现影响边界、业务或安全语义、技术方向、验证负担、不可逆性等否决信号时，再按实际触发扩展能力或升级门禁。触发义务完成后收缩回轻量路径。

**决策点内联锚点**。执行循环中具有否决权的决策点（校准、选择动作）旁内联压缩的触发锚点（`[决: …]`），让否决信号与决策位置相邻，而不是只出现在远处的深度或门禁章节。锚点只是检索线索，不替代判定：其完整触发条件和执行要求必须保留在常驻入口（强约束版）、触发表与专项方法（Mini 版）或可路由模块（Self 版）中；修改否决信号清单、门禁触发表或模块触发表时，必须同步更新对应锚点。

**循环校验**。工具调用成功不等于任务步骤成功；每个逻辑动作后都要比较预期和实际，并据此更新下一轮状态。

**证据复用与按需取证**。Agent 先复用仍然新鲜、直接且适用于当前范围的证据；只在缺失、过期、冲突或范围变化时补充下一动作所需的规则、项目事实和运行证据，不以工具调用数量证明充分性。

**版本独立**。`mini/`、`rules/` 与 `self/` 分别定义完整的接入边界。

**跨 Agent 可移植**。规则使用读取、搜索、修改、执行和验证等抽象行为，不绑定特定 Code Agent 的工具名称或内部实现。

**技术方向自主但不覆盖用户方向**。用户可只给目标与边界，由 Agent 依据文档、代码、配置、环境和验证结果识别或选择语言、技术栈与实现方向；用户明确指定技术时先核对兼容性，可行则遵循，冲突或会造成重大迁移时展示证据和选项。只有选择会改变高影响边界或依赖无法推导的非技术取舍时才升级确认。

**性能与工具链可证**。性能、容量或资源结论需要可重复基线和同负载比较；生成器、编译器、锁文件、迁移与部署产物都纳入影响分析。仓库、用户级和全局配置按实际作用域判断，只修改授权且生效的最小层级。

**可编排也可被编排**。支持单 Agent、主 Agent 调用多个子 Agent，以及当前 Agent 作为子 Agent 返回结构化证据；只有委派收益高于协调和复核成本时才扩展，任务收敛后恢复单 Agent。委派不转移最终验证责任。共享工作区默认采用单写者模型；子 Agent 默认不再委派，只有平台具备可追踪层级且任务明确授权时才例外允许，后代任务涉及写入时还必须具备独立工作区或等价隔离。

**设计方式中立**。不把任何编程范式、分层模型或设计模式当作默认答案。采用 Mini 版时按 `mini/methods/neutral-design.md`，采用强约束版时按 `rules/coding-principles.md`，采用 Self 独立版时遵循 `self/core.md` 的最小充分原则；不要跨版本拼接最高规则。

**证据分层**。当前实现以代码、配置和运行结果为准；目标行为以用户确认的需求、业务规则和有效决策为准。两者冲突时显式标记，不擅自裁决；无法推导的内容标注“需用户提供”。

## 适用场景

适合嵌入任何使用 AI Coding Agent 的团队项目，作为 Agent 行为的统一标准。

## 规则回归验证

`eval/` 存放规则维护用的行为回归基准：前 4 个案例取材真实开源项目 issue（并发竞态诊断、金额门禁、依赖 major 升级、决策回查），另有技术选型、多 Agent、设计方式中立、动态执行深度、性能证据和工具链作用域综合场景。每次修改规则后，将基准任务交给加载了被测规则的 Agent 并核对检查点，防止规则变更引入行为退化。用法与判定标准见 `eval/README.md`。

跨文件规则引用使用“文件路径 + 章节标题”而不是数字章节号。维护规则标题或引用后，运行 `py eval/check_rule_references.py`（也可用环境中的 `python`）检查目标文件、标题及遗留数字引用。
