# Code Agent Rules

> 让 AI Coding Agent 依据项目证据形成认知、执行改动并验证结果。

## 这是什么

一个可以被 AI Coding Agent 加载的**规则集**。它不是仅供人类阅读的编码规范文档，而是直接嵌入 Agent 工作流的**行为约束与认知锚点**：

- 什么能改、什么不能改
- 改动前先获取什么证据、做什么评估
- 遇到 Bug 按什么流程诊断
- 什么时候该抽象、什么时候不该抽象
- 业务逻辑怎么分析、数据流怎么追踪

仓库提供两份可独立采用的版本：`rules/` 是配套固定项目文档体系的强约束版，`self/` 是从现有项目证据动态形成认知的自适应版。两份版本互不依赖，使用方可按场景单独复制、加载和维护。

## 目录结构

```text
.
├─ rules/        # 强约束版：行为总纲、分析方法和编码约束
│  ├─ agent.md   # 强约束版入口：固定文档体系、能力路由和执行门禁
│  ├─ coding-principles.md # 中立的编码行为、设计判断与验证边界
│  ├─ technology-selection.md # 从项目证据识别技术栈并在边界内自主选型
│  └─ agent-collaboration.md # 多 Agent 编排与子 Agent 契约
├─ documents/    # 强约束版配套的项目事实与决策记录示例
├─ self/         # Self 独立版：最小核心与按需能力模块
│  ├─ core.md    # Self 版默认入口（30～60 行）
│  ├─ README.md  # Self 版说明及模块索引
│  ├─ context.md # 模块：上下文与项目认知
│  ├─ diagnosis.md # 模块：疑难 Bug 诊断
│  ├─ change.md  # 模块：兼容与迁移
│  ├─ security.md # 模块：安全控制
│  ├─ technology.md # 模块：技术识别与自主选型
│  └─ collaboration.md # 模块：多 Agent 协作
├─ eval/         # 规则回归验证基准（维护者使用）
├─ AGENTS.md     # 跨工具通用入口（Claude Code / Codex / Copilot / Cursor / Trae 自动读取）
├─ CLAUDE.md     # Claude Code 专属入口
└─ README.md     # 本规则仓库说明
```

## 规则清单

| 文件 | 定位 | 核心内容 |
|------|------|----------|
| `rules/agent.md` | 循环控制总纲 | 任务状态恢复、风险分级、能力路由、动作校验、暂停条件和循环控制 |
| `self/core.md` | Self 版最小入口 | 目标、证据、最小动作、反馈、安全停机和完成门禁 |
| `self/README.md` | Self 版说明与能力索引 | 独立使用方式及按触发场景加载上下文、Bug、迁移或安全模块 |
| `rules/business-analysis.md` | 业务决策 | 变更影响分析、决策四步框架、冲突回查、优先级体系 |
| `rules/data-flow-methodology.md` | 数据追踪 | 六步追踪法、固定推导顺序、节点标注规范 |
| `rules/data-structure-analysis.md` | 数据建模 | 实体识别、关系建模、字段推导、索引策略、写入策略阶梯 |
| `rules/destructive-analysis.md` | 风险控制 | 变更分级、事前预测、事中检测、扩展-收缩迁移模式 |
| `rules/diagnosing-bugs.md` | 排错流程 | 反馈回路→复现最小化→可证伪假设→插桩→修复→清理 |
| `rules/document-init.md` | 文档体系 | 8 类项目文档的创建时机、内容基准、初始化原则 |
| `rules/coding-principles.md` | 编码与设计准则 | 简洁与精准修改、证据驱动的实现选择、抽象判断、验证及安全边界 |
| `rules/technology-selection.md` | 技术自主决策 | 从需求、文档、代码和环境识别语言/技术栈，在工程边界内选择技术方向 |
| `rules/agent-collaboration.md` | 多 Agent 协作 | 主/子 Agent 责任、任务包、单写者与隔离边界、结果复核与验收 |
| `self/technology.md` | Self 技术选型模块 | 不预设语言或框架，按证据与影响自主识别、选择和验证 |
| `self/collaboration.md` | Self 多 Agent 模块 | 编排、委派、子 Agent 返回和全局验收边界 |

`documents/` 下提供 8 类项目文档的最小示例。示例用于展示结构和写法，接入实际项目后必须依据代码与真实业务资料替换。

## 怎么用

在 AI Coding Agent 的系统提示或项目配置中选择一份版本引用。以 Cline 为例，可将所选版本配置为自动加载；其他 Agent 平台对应机制类似：

- **强约束版**：使用 `rules/agent.md` 及其专项规则，并配套 `documents/`。含固定项目文档体系与决策回查（组织记忆）。适合团队需要统一项目记忆、明确门禁和可审计流程的场景。
- **Self 独立版**：默认只加载 `self/core.md`；触发复杂场景时再依据 `self/README.md` 加载本目录对应模块。适合资料形态不固定，希望 Agent 从代码、配置、测试、运行结果、历史和用户说明中动态形成项目认知，并自主确定语言、技术栈和实现方向的场景。Self 版不提供决策档案与回查等组织记忆能力；长周期项目如需该能力，应采用强约束版或自行补充决策记录。

### 强约束版最小起步

先加载 `rules/agent.md` 及当前任务实际触发的专项规则；`documents/` 不要求一次建齐。首次任务只创建当前动作依赖的项目文档，其他文档在相应场景首次出现时按需补充。文档缺失本身不阻塞任务，只有缺失信息会影响正确性时才暂停。具体创建条件和最小内容见 `rules/document-init.md`。

### 两版组合边界

两份版本不是连接关系、替代层或兼容层，也不要求互相引用。选择其中一份即可独立运行；组合不是仓库的默认用法，也不在现有回归基准覆盖范围内。若使用方确需组合，只选择一个版本作为总控入口，另一版本仅作为按需方法补充；出现重叠或冲突时以总控版本为准，不将 `rules/agent.md` 与 `self/core.md` 同时设为并列最高规则。

Self 独立版不会给模型增加其原本没有的推理或工具能力。对成熟 Agent，它主要用于降低长任务目标漂移、证据与目标混淆、假阳性验证和高风险误操作；简单任务上的增益通常很小。若平台系统提示已经提供等价约束，应在接入时选择或合并，避免增加上下文和流程负担。

两份版本都不替代具体平台的工具调度，也不要求平台必须支持多 Agent。协作规则是任务边界和验收协议，不提供文件锁、事务或工作区隔离；平台不能证明独立工作区时，子 Agent 默认只读并由单一所有者串行整合。平台支持委派时，同一规则既可作为主 Agent 的编排约束，也可作为子 Agent 的执行契约；平台不支持时由单 Agent 按相同循环执行。它们各自在自己的规则边界内约束 Agent 的观察、执行和反馈循环：

```
任务开始/恢复
   ↓
校准目标、成功标准、状态和风险
   ↓
加载下一动作所需的最小知识
   ↓
选择并执行一个可验证动作
   ↓
校验实际结果并更新上下文
   ↓
继续 / 暂停 / 阻塞 / 回退 / 完成
```

强约束版按任务分级决定文档和门禁深度；Self 独立版依据影响、不确定性、后果、可逆性和可观测性动态调整认知与验证深度。

## 跨工具使用

规则正文与具体工具无关（见「设计原则 · 跨 Agent 可移植」）。本仓库在根目录与各工具约定路径放置了**入口文件**，它们只做一件事：告诉 Agent「去读哪些规则文件」，不把全部内容塞进上下文——这本身也符合规则要求的「按需取证」原则。

### 自动加载路径

| 工具 | 自动加载的入口文件 | 备注 |
|------|-------------------|------|
| Claude Code | `CLAUDE.md` 或 `AGENTS.md` | 两者皆支持 |
| OpenAI Codex | `AGENTS.md` | 多数 Agent 的事实标准 |

### 选择版本

在所用工具的入口文件中，取消注释「强约束版」或「Self 独立版」那一行即可（两版独立，不要同时启用）：

- **强约束版**：读取并遵循 `rules/agent.md`，按其中“能力路由与知识加载”章节按需加载专项规则与 `documents/`。
- **Self 独立版**：读取并遵循 `self/core.md`，复杂场景按 `self/README.md` 触发表加载 `context` / `diagnosis` / `change` / `security` / `technology` / `collaboration` 模块。
- 两版均不预设编程语言、框架或数据库；相关选择按各自的技术选型规则从项目证据与用户边界中得出。两版均可被主 Agent 加载，也可作为子 Agent 的任务执行规则。
- 两版均不预设特定编程范式、分层模型或设计模式；Agent 依据现有代码、问题性质和验证成本决定实现方式，规则只限制复杂度、风险和可验证性。


## 设计原则

**风险驱动**。改动风险越大，流程越重；风险越低，流程越轻。不确定时自动升级。

**循环校验**。工具调用成功不等于任务步骤成功；每个逻辑动作后都要比较预期和实际，并据此更新下一轮状态。

**按需取证**。Agent 不无目标扫描资料，而是在每轮决策前只获取下一动作所需的规则、项目事实和运行证据。

**版本独立**。`rules/` 与 `self/` 分别定义完整的接入边界。

**跨 Agent 可移植**。规则使用读取、搜索、修改、执行和验证等抽象行为，不绑定特定 Code Agent 的工具名称或内部实现。

**技术方向自主**。用户负责目标、业务与工程边界；Agent 依据文档、代码、配置、环境和验证结果识别或选择语言、技术栈与实现方向。只有选择会改变高影响边界或依赖无法推导的非技术取舍时才升级确认。

**可编排也可被编排**。支持单 Agent、主 Agent 调用多个子 Agent，以及当前 Agent 作为子 Agent 返回结构化证据；委派不转移最终验证责任。共享工作区默认采用单写者模型；子 Agent 默认不再委派，只有平台具备可追踪层级和隔离工作区且任务明确授权时才例外允许。

**设计方式中立**。不把任何编程范式、分层模型或设计模式当作默认答案。采用强约束版时按 `rules/coding-principles.md` 从项目证据判断；采用 Self 独立版时遵循 `self/core.md` 的最小充分原则，不跨版本补充规则。

**证据分层**。当前实现以代码、配置和运行结果为准；目标行为以用户确认的需求、业务规则和有效决策为准。两者冲突时显式标记，不擅自裁决；无法推导的内容标注“需用户提供”。

## 适用场景

适合嵌入任何使用 AI Coding Agent 的团队项目，作为 Agent 行为的统一标准。

## 规则回归验证

`eval/` 存放规则维护用的行为回归基准：前 4 个案例取材真实开源项目 issue（并发竞态诊断、金额门禁、依赖 major 升级、决策回查），另有技术自主选型、多 Agent 协作和设计方式中立综合场景。每次修改规则后，将基准任务交给加载了被测规则的 Agent 并核对检查点，防止规则变更引入行为退化。用法与判定标准见 `eval/README.md`。

跨文件规则引用使用“文件路径 + 章节标题”而不是数字章节号。维护规则标题或引用后，运行 `py eval/check_rule_references.py`（也可用环境中的 `python`）检查目标文件、标题及遗留数字引用。
